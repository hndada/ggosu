# 손가락 상태 기반 난이도 POC

명령은 저장소 루트에서 실행한다. CLI·전용 모델·보고서 스크립트는 모두 poc 아래에 있으며,
모델은 `internal/difficulty`에 있다. [POC 목차](../README.md).

`difficulty.Analyze`는 `chart.Chart`를 읽어 손가락의 누름·유지·해제 동작을 배치하고,
손가락별 동작 비용과 간섭 비용을 계산한다. 짧은 구간의 비용 합을 순간 strain으로,
내림차순 순간 strain의 weighted sum을 난이도로 사용한다.

첫 검증 대상은 **같은 손가락별 속도와 같은 입력량의 chord/trill**이다.
계수는 실험용 예시이며, 계산 검증은 생체역학 계수나 실제 체감 난이도의 검증을 뜻하지 않는다.
곡 선택창 레벨은 이 모델의 기본 프로필(레인 절반씩 양손) 값을 잠정치로 쓴다(`difficulty.Rate`). 게임 점수·PP에는 연결하지 않는다.

현재 모델은 `finger-motion-v4-poc`다. 손가락별 잔류 부담을 유지하고 자유 휴식·유지 상태를
구분해 회복하며, 반복 부담을 별도 비용으로 기록한다. 아래 v1 비교 표는 `-repeat-gain 0`으로
재현하는 기초 동작·행렬 통제 결과다. 최신 변경은 문서 끝의 **반복 가산 상한 축소**에 있다.

## 실행

```powershell
# 동일 밀도 chord/trill과 LN 유지 손가락의 부담 비교
go run ./cmd/poc/difficulty

# Chord끼리: 속도·키 수·손 배치·교대 조합 10조건
go run ./cmd/poc/difficulty -suite chords

# 공유 손가락과 양손 교대의 차이가 휴식에 따라 줄어드는지 비교
go run ./cmd/poc/difficulty -suite recovery

# 롱노트 간섭·다중 유지·해제 후 복귀·순수 유지 시간 12조건
go run ./cmd/poc/difficulty -suite holds

# 간섭의 누적 비율만 변경. 1은 기존 v2 계산을 재현한다.
go run ./cmd/poc/difficulty -suite holds -interaction-load 1

# 반복 보정 제거: 기존의 동일한 결과를 재현
go run ./cmd/poc/difficulty -suite recovery -repeat-gain 0

# 실제 계산에 사용한 합성 채보 파일도 내보내기
go run ./cmd/poc/difficulty -suite chords -charts artifacts/08-difficulty/new-charts

# 계수를 수정한 같은 손 두 손가락 프로필로 동일 실험 반복
go run ./cmd/poc/difficulty -profile artifacts/08-difficulty/profile-2fingers.json

# 손 상태·위치·보정 배수·비용 분해·구간별 순위까지 저장
go run ./cmd/poc/difficulty -out artifacts/08-difficulty/new-comparison.json

# 배속에 따른 실제 동작 시간 압축
go run ./cmd/poc/difficulty -rate 2

# 실제 4K 채보: 레인마다 사용할 손을 명시
go run ./cmd/poc/difficulty -input songs/demo/demo.osu -hands 0,0,1,1

# JSON 프로필로 손가락별 기준 시간과 상호작용 계수를 지정
go run ./cmd/poc/difficulty -input songs/demo/demo.osu -profile artifacts/08-difficulty/profile-4k.json

# 노트별 strain 검토 페이지(게임 -debug 표기와 같은 값). -hands·-profile을 생략하면 게임과 같은 손 배치
go run ./cmd/poc/difficulty -input songs/demo/demo.osu -html artifacts/08-difficulty/strain-demo.html
```

기본 모듈 캐시에 쓰기 권한이 없는 환경에서는 현재 PowerShell 세션에 다음을 적용한다.

```powershell
$cacheRoot = Join-Path (Get-Location) '.cache'
$env:GOMODCACHE = Join-Path $cacheRoot 'mod'
$env:GOCACHE = Join-Path $cacheRoot 'build'
$env:TEMP = Join-Path $cacheRoot 'tmp'
$env:TMP = $env:TEMP
```

`-out`은 기존 파일을 덮어쓰지 않는다. 출력 디렉터리는 미리 만든다.
`-profile`로 실제 채보 운지를 지정하거나, 같은 손 두 손가락 프로필로 통제 실험의 계수를 바꿀 수 있다.
다른 손 통제군은 같은 기본 동작 계수를 유지하고 쌍별 간섭만 제거한다.
`-json`은 전체 보고서를 표 대신 표준 출력으로 내보낸다.
기본값은 window=200ms, weight=0.9, power=1, tap-hold=50ms, rate=1이다.
잔류 부담 옵션은 recovery=250ms, hold-recovery=0.1, load-limit=4, repeat-gain=4다.
v3의 interaction-load 기본값은 0.25이며, 0~1 범위에서 즉시 비용과 잔류 부담에 넣는 작업량을 분리한다.
`-recovery`는 자유 휴식 중 부담이 1/e로 감소하는 시간이며, `-hold-recovery`는 그 회복 속도에 대한 비율이다.
`-repeat-gain 0`은 반복 추가 비용을 완전히 끈다.

## 불변조건과 동작 배치

- 레인 하나에는 고정된 손가락 하나를 배정한다. 원본 타임스탬프를 수정하지 않는다.
- 누름은 위치 0→1, 해제는 1→0의 선형 움직임이다. 위치는 실제 측정값이 아닌 모델상의 진행도다.
- 누름은 노트 시각에 완료한다. 첫 노트도 기준 누름 시간만큼 미리 준비한다.
- 새로운 누름 전에 이전 누름의 해제를 완료한다. 진행 중인 손가락을 순간적으로 초기화하지 않는다.
- 일반 탭은 최대 `TapHold` 동안 유지한다. 다음 노트가 있으면 유지 시간을 입력 간격의 1/4 이하로 제한한다.
- LN은 끝 시각까지 위치 1을 유지하고, 끝 시각부터 해제 움직임을 시작한다.
- 다음 노트까지 시간이 부족하면 이전 해제와 다음 누름 시간을 기준 시간 비율로 압축한다.
- 두 움직임에 양의 시간을 줄 수 없는 LN 끝/다음 누름의 동일 시각은 오류로 보고한다.

예를 들어 LN 끝과 다음 노트 사이가 40ms이고 기본 해제·누름이 각각 50ms라면,
해제 20ms + 누름 20ms로 배치한다. 양쪽 움직임의 시간 보정은 각각 2.5다.

이 배치는 결정적인 한 가지 준비 정책이다. 실제 운지의 최적화나 판정창 안의
조기 해제·입력 이동을 탐색하는 solver는 아니다. LN 해제 시각은 게임 판정 결과를 계산하는
시각이 아니라 모델상의 위로 움직이기 시작하는 시각이며, 완전한 복귀에는 추가 시간이 든다.

## 비용 계산

```text
손가락 비용 = 자신의 동작 비용 + 자신에게 배분된 간섭 비용 + 반복 비용
시간 보정 = max(1, 기준 동작 시간 / 배치된 동작 시간)^power
```

누름·해제 한 번의 기본 비용에 시간 보정을 곱한다. 이를 실제 움직임 구간에 균등하게
분배해서 적분한다. 다른 손가락의 동작이나 구간 경계 때문에 보고서가 여러 조각으로
나뉘어도 같은 움직임을 여러 번 계산하지 않는다.

상호작용 표의 행은 손가락 A, 열은 손가락 B의 상태다. 상태 순서는
`rest=0`, `press=1`, `hold=2`, `release=3`이다.
각 항목은 `{a: A가 받는 추가 비용, b: B가 받는 추가 비용}`이다.
`Pair.A < Pair.B`인 한 쌍을 한 번만 평가하고, 양쪽 부담을 각각 기록한다.
예를 들어 `pairs[0].costs[1][3]`은 A 누름/B 해제의 두 비용이고,
`pairs[0].costs[2][1]`은 A 유지/B 누름의 두 비용이다.

기본 프로필의 같은 손 안 예시 계수:

| A 상태 | B 상태 | A 비용 | B 비용 |
|---|---|---:|---:|
| 누름 | 누름 | 0.05 | 0.05 |
| 해제 | 해제 | 0.05 | 0.05 |
| 누름 | 해제 | 0.35 | 0.35 |
| 해제 | 누름 | 0.35 | 0.35 |
| 누름 또는 해제 | 유지 | 0.25 | 0.20 |
| 유지 | 누름 또는 해제 | 0.20 | 0.25 |

모두 정지해 있거나 rest인 손가락과의 기본 간섭은 0이다. 기본 프로필에는 손이 다른 쌍을
만들지 않는다. 손가락 간 거리·해부학 차이를 측정한 값은 아니므로 실제 운지에 맞게
손가락별 기준 시간과 쌍별 행렬을 수정해야 한다.

LN A 유지 중 B가 움직이면 A의 기본 동작 비용은 0이어도 유지 간섭 비용은 발생한다.
이때 간섭은 B의 `시간 보정 / 동작 길이`를 구간 길이에 곱해 양쪽에 배분한다.
둘 다 움직이면 두 손가락의 해당 intensity 중 큰 값을 쓰는 것이 이 POC의 명시적 규칙이다.
겹치는 움직임 전체를 한 번에 같은 길이로 취급하지 않고 실제 겹친 구간만 적분한다.

순수하게 오래 누르는 것 자체의 유지 비용과 읽기·타이밍 동기화 부담은 아직 없다.
고정된 손가락이 다른 손가락의 움직임으로 받는 부담과 그에 따른 잔류 부담은 구현되어 있다.

## 순간 strain과 난이도

```text
순간 strain = 고정 길이 창 안에 들어온 모든 손가락 비용의 합
난이도 = s1 + weight*s2 + weight²*s3 + …  (s1 >= s2 >= s3)
```

창은 첫 실제 누름 노트 시각을 기준으로 고정한다. 준비 움직임은 앞쪽 창에 기록한다.
차트 전체의 시각을 이동해도 상대 창 경계와 계산 결과는 유지된다. 창 너비는 비용 합의
총량을 바꾸지 않지만, 순간 strain의 분포와 난이도 값은 바꿀 수 있다.

고정 창 안에서의 세부 배치 차이와 긴 구간의 지속성에는 여전히 집계 방식의 한계가 있다.
geometric weight는 어려운 구간이 많아지면 길이 효과가 포화한다. window/weight 값은
계산 검증과 별도로 실제 플레이 비교를 통해 선택해야 한다.

## 첫 비교의 통제 조건과 결과

24주기를 생성하고 시작 준비·마지막 해제를 제외한 가운데 20주기를 측정한다.
주기는 200ms이며 각 손가락은 초당 5회, 합계 초당 10회 누른다.
탭 유지 50ms, 누름·해제 기준 시간 각각 50ms다.

Chord는 두 손가락이 같은 방향으로 움직인다. Trill은 두 손가락의 입력을 100ms 옮겨,
한 손가락의 누름과 다른 손가락의 해제 움직임이 겹치도록 만든다.

| 비교 | 기본 동작 비용 | 간섭 비용 | 총 strain | 난이도 |
|---|---:|---:|---:|---:|
| Chord / 같은 손 | 80 | 4 | 84 | 36.8938 |
| Trill / 같은 손 | 80 | 28 | 108 | 47.4349 |
| Chord / 다른 손 | 80 | 0 | 80 | 35.1369 |
| Trill / 다른 손 | 80 | 0 | 80 | 35.1369 |

Trill이 더 높게 나온 것은 **반대 방향 동작의 예시 계수를 더 크게 설정했기 때문**이다.
두 패턴의 상대적인 실제 난이도가 증명된 것은 아니다. 행렬을 제거하면 결과가 같고,
반대 방향 계수를 동시 움직임과 같게 바꿔도 같아지는지 테스트한다.

LN 0~1000ms + 다른 손가락의 400ms 탭에서는 탭의 누름·해제 중,
LN 손가락에 동작 비용 0 / 간섭 비용 0.4가 기록된다. 움직이는 손가락의 간섭 비용은 0.5다.

## 구성과 검증

- `internal/difficulty/profile.go`: 손가락별 기준 시간·비용, 쌍별 상호작용 표, 분석 옵션.
- `internal/difficulty/motion.go`: 다음 입력을 고려한 동작 배치와 시간 보정.
- `internal/difficulty/analyze.go`: 연속 위치·방향 상태, 비용 적분, 창 집계와 순위.
- `cmd/poc/difficulty`: 통제 실험과 실제 채보의 분석·보고서 출력.

`go test ./...`, `go vet ./...`를 통과했다. 테스트는 다음을 확인한다.

- Chord/trill의 입력량·손가락별 속도·기본 비용 일치.
- 행렬 제거·중립 행렬·다른 손 통제군에서 결과 일치.
- 새 노트 없는 LN 유지 손가락의 간섭 비용.
- 완전한 복귀 후 다음 누름, LN 유지 보존, 짧은 간격의 시간 압축.
- 구간을 더 잘게 나눠도 비용 총량 보존.
- 시간 평행 이동·동시 노트 순서·표시용 노트·무음 suffix의 불변성.
- 배속 평가가 원본 채보 시각을 수정하지 않음.
- 중복 쌍·잘못된 계수·지원하지 않는 동작의 오류 처리.

현재는 tap/hold와 표시용 fake만 지원하며 roll/mine/lift/scratch는 명시적인 오류다.
각 레인이 독립된 손가락으로 동작한다는 가정이므로 스크래치·발판·다중 레인 운지에는
별도 모델이 필요하다. 실제 사람의 손가락 움직임과 오류율을 측정하는 검증은 다음 단계다.

## 원본 채보와 chord 간 추가 비교

`-charts`는 각 분석에 실제 사용한 채보를 `01.ggc`, `02.ggc`, …로 내보낸다.
레이아웃에는 손가락 이름과 손 그룹이 들어 있으며, JSON 보고서에도 같은 원본 채보를 포함한다.
예시 그림은 이 `.ggc`의 노트를 직접 읽어서 그린다.

기존 chord/trill은 두 레인에 24주기를 생성한 합성 채보다. Chord는 A/B가 모두
0, 200, 400, …ms에 등장한다. Trill은 A가 0, 200, 400, …ms이고 B가
100, 300, 500, …ms다. 두 경우 각각 노트 48개, 손가락당 초당 5회다.

`-suite chords`의 기본 운지는 A/B/C가 손 0, D/E/F가 손 1이다.
새 비교는 모든 조건에서 같은 600~6600ms의 6초를 측정한다.
이전 chord/trill의 4초 측정과는 비교 길이가 다르므로 난이도 값을 직접 섞어 비교하지 않는다.

| 배치 | 반복 간격 | notes/s | 동작 비용 | 간섭 비용 | 난이도 |
|---|---:|---:|---:|---:|---:|
| AB | 400ms | 5 | 60 | 3 | 20.1098 |
| AB | 200ms | 10 | 120 | 6 | 40.2196 |
| AC | 200ms | 10 | 120 | 6 | 40.2196 |
| AD | 200ms | 10 | 120 | 0 | 38.3044 |
| AB↔AC | 200ms | 10 | 120 | 6 | 40.2196 |
| AB↔DE | 200ms | 10 | 120 | 6 | 40.2196 |
| AB | 100ms | 20 | 320 | 16 | 107.2522 |
| ABC | 200ms | 15 | 180 | 18 | 63.2022 |
| ABD | 200ms | 15 | 180 | 6 | 59.3717 |
| ABC | 300ms | 10 | 120 | 12 | 53.0947 |

AB/200ms와 ABC/300ms는 입력 밀도와 동작 비용은 같지만 쌍 개수와 구간 집중도가 다르다.
ABC/200ms와 ABD/200ms는 키 수·속도가 같고 같은 손에 속하는 쌍 개수만 다르다.

위 표는 반복 비용을 끈 v1 통제 결과다. 현재 예시 계수는 같은 손의 모든 손가락 쌍에 같아서 AB와 AC를 구분하지 않는다.
해당 쌍의 계수를 달리하면 구분되는지도 테스트한다. AB 반복과 두 종류의 교대는
이 속도에서 복귀 시간을 압축할 필요가 없고 잔류 피로도 없어 같은 값이다.
실제 운지에서 같은 난이도라는 뜻이 아니라 현재 모델이 그 차이를 반영하지 않는다는 뜻이다.

v2에서는 아래와 같이 반복 부담을 추가해 AB↔AC와 AB↔DE를 구분한다.

원본 파일·그림·계산 결과는 [추가 검증 보고서](../../../artifacts/08-difficulty/chord-review/report.md)에 정리했다.
`cmd/poc/difficulty/scripts/plotdifficulty.py`는 Pillow로 저장된 채보와 실제 계산 JSON을 읽어 그림을 재생성한다.

## 잔류 부담과 회복 검증

손가락마다 0~`LoadLimit` 사이의 부담 기억을 둔다. 기존 동작·간섭 비용이 발생하면
증가하고, 이동 중에는 회복하지 않으며, 유지 중에는 자유 휴식의 0.1배로 회복한다.
0.1, 250ms, 최대 부담 4와 반복 가산 상한 0.5는 미보정 실험값이다.

```text
현재 비용 = 기존 비용 × (1 + RepeatGain × (잔류 부담 / LoadLimit)²)
```

기본 보정 배수는 1~1.5로 제한된다. 잔류 부담을 채우는 것은 **기존 비용**이며,
늘어난 반복 비용을 다시 부담에 넣지 않는다. 자체 증폭을 방지하면서 개인 손가락에
반복되는 입력과 다른 손가락의 간섭을 이력으로 남긴다.

동작 구간 안에서도 부담이 변하므로 상태 변화와 비용을 해석적으로 적분한다.
보고서의 창 크기나 구간 분할 수가 부담·비용 총량을 바꾸지 않는다.
부분 구간 측정은 `Segment.Costs`로 다시 적분한다. 전체 반복 비용에 길이 비율을 곱하면 안 된다.
이전 부담과 이후 부담은 상태의 `load_start`/`load_end`, 추가 비용은 `repeat`에 기록한다.

아래 표와 비율은 이전 v2(`-repeat-gain 4 -interaction-load 1`)의 검증 기록이다.
같은 6초의 200ms chord 비교:

| 배치 | 동작 비용 | 간섭 비용 | 반복 비용 | 난이도 |
|---|---:|---:|---:|---:|
| AB 반복 | 120 | 6 | 250.8987 | 120.7425 |
| AB↔AC | 120 | 6 | 161.1837 | 91.9398 |
| AB↔DE | 120 | 6 | 71.4688 | 63.1371 |

AB↔AC는 A에 입력이 집중된다. 현재 준비 정책에서 A의 자유 휴식은 50ms이며,
AB↔DE는 각 손가락이 250ms 쉰다. 같은 행렬과 같은 입력량에서 잔류 부담으로 차이가 생긴다.
AB↔AC가 약 1.456배 높게 계산된다. 실제 체감 차이의 크기까지 보정된 값은 아니다.

회복 시험은 각 속도에서 같은 가운데 20회 chord, 노트 40개를 측정한다.
더 느린 속도에서는 관측 시간도 길어지므로 다른 속도끼리의 절대 난이도보다
각 속도에서 두 배치의 상대 비율을 본다.

| chord 간격 | AB↔AC | AB↔DE | 비율 |
|---|---:|---:|---:|
| 200ms | 84.0763 | 57.8229 | 1.4540 |
| 400ms | 32.9242 | 29.6541 | 1.1103 |
| 800ms | 29.1423 | 28.6289 | 1.0179 |
| 1600ms | 28.6089 | 28.5888 | 1.0007 |

반복 비용을 끄면 모든 속도에서 두 배치가 다시 같다. 행렬을 제거해도 공유 손가락의
잔류 부담에 의한 순위는 유지된다. 패턴 이름이나 같은 손 여부에 별도 보너스를 넣지 않았다.

기존 통제 테스트는 `RepeatGain=0`으로 유지하고, v2 테스트는 다음을 별도로 확인한다.

- AB↔AC > AB↔DE, 휴식 증가에 따른 비율 수렴, 행렬·반복 비용 제거 통제.
- 부담 상한과 반복 보정 상한, 유지·자유 휴식의 회복 차이.
- LN 손가락에 새 움직임 없이 간섭에 의한 부담 증가.
- 구간 분할·부분 적분·시각 이동·동시 노트 순서·배속 원본 보존.
- 반복 보정 강도를 바꿔도 잔류 부담 자체는 바뀌지 않음.

손이 다른 chord/trill의 유한 관측 구간에서는 초기 상태에서 쌓이는 이력과 100ms 위상 차이로
작은 차이가 남을 수 있다. 반복 비용을 끈 기초 동작 통제에서는 원래의 정확한 동일성이 유지된다.

소스는 `internal/difficulty/load.go`와 `internal/difficulty/analyze.go`, 추가 시험은 `cmd/poc/difficulty/recovery_test.go`다.
[v2 회복 검증 보고서](../../../artifacts/08-difficulty/recovery/report.md)에 해당 버전의 결과와 원본 채보를 보존했다.

## 롱노트 검증

아래 표는 간섭을 전부 누적했던 v2(`-interaction-load 1`)의 검증 기록이다.
v3 기본값의 현재 결과와 감소 폭은 다음 절에서 비교한다.

`-suite holds`는 6개 손가락의 고정 운지에서 12조건을 계산한다.
A/B/C는 손 0, D/E/F는 손 1이다. 반복 보정과 행렬 계수는 변경하지 않았다.

유지 중 입력 비교는 500~5500ms의 같은 5초를 관측한다. LN은 0~6000ms 유지하고,
시작·끝 움직임을 측정 구간에서 제외한다. 기준군은 A를 처음에 한 번 탭하고 놓는다.
모든 유지 구간 비교에는 탭 24개(4.8 notes/s)가 들어간다.

| 조건 | 동작 비용 | 간섭 비용 | 반복 비용 | 난이도 |
|---|---:|---:|---:|---:|
| A 해제 상태 + B 반복 | 48 | 0 | 85.4983 | 53.4226 |
| A 유지 + B 반복 | 48 | 21.6 | 131.7509 | 80.5316 |
| A 유지 + D 반복 | 48 | 0 | 85.4983 | 53.4226 |
| A 유지 + B/C 교대 | 48 | 21.6 | 49.0278 | 46.7979 |
| A/C 유지 + B 반복 | 48 | 43.2 | 180.5909 | 108.5279 |
| A/D 유지 + B 반복 | 48 | 21.6 | 131.7509 | 80.5316 |
| A 유지 + B/C chord | 48 | 24 | 52.8185 | 75.8979 |

같은 손의 LN A는 이 관측 구간에서 새 누름 0회·동작 비용 0이어도 간섭 비용 9.6과
반복 비용을 받는다. B/C 교대는 LN A에 전달되는 기본 간섭과 반복 비용은 그대로이고,
움직이는 손가락의 반복 집중이 줄어든다. 같은 손 LN을 두 개 유지하면 각 유지 손가락에
수신 비용이 기록된다. 다른 손 LN의 추가는 이 예시 행렬에서 별도 간섭을 만들지 않는다.

해제 후 같은 손가락의 다음 입력은 LN 끝과의 간격 200ms/40ms를 비교했다.
전체 동작 비용은 각각 4/7이다. 40ms에서는 해제와 다음 누름을 20ms씩 배치하며,
각 시간 보정은 2.5이고 손가락 위치는 1→0→1로 연속된다.
같은 시각의 LN 끝·다음 누름은 복귀 시간이 없으므로 명시적 오류다.

A가 1000ms부터 해제하고 B가 1025ms에 누름을 완료하는 조건도 확인했다.
1000~1025ms에는 A 해제/B 누름이 겹치며 각각 0.175의 반대 동작 간섭을 받는다.
이때 B는 이미 반쯤 눌린 위치에서 진행 중인 움직임을 이어간다.

2배속에서는 원본 LN의 6000ms 끝 시각을 수정하지 않고 평가상 3000ms로 해석한다.
유지 관측 구간에는 여전히 LN 손가락의 새 움직임이 없다. 창을 200ms에서 7ms로
바꿔도 측정한 동작·간섭·반복 비용 총량이 보존된다. 유지 회복 속도를 높이면 유지
손가락의 반복 비용이 줄며, 행렬을 제거하면 유지 손가락의 수신 비용은 0으로 돌아간다.

검증으로 확인한 제한도 있다. 현재는 순수 유지 자체의 작업량이 없어서 단독 LN의
동작 비용은 1초/4초 모두 2이고, 더 오래 유지할수록 해제 전에 회복이 더 일어난다.
실제 계산 난이도는 2.2171→2.0731이다. 유지 시간이 길어지는 부담은 아직 모델에 없다.
이 동작을 테스트로 보존하고 보고서에 명시했으며, 검증 과정에서 임의의 길이 보정을 추가하지 않았다.

[롱노트 보고서와 원본 채보](../../../artifacts/08-difficulty/holds/report.md)에 기본 조건과
2배속·유지 회복 변경 결과를 보존했다. `cmd/poc/difficulty/scripts/plotholds.py`는 원본 `.ggc`에서
LN 유지 구간과 실제 탭 배치를 그린다.

## 간섭 누적 비율 분리

이 절의 수치는 v3(`-repeat-gain 4`)의 검증 기록이다.

v2는 즉시 간섭 비용을 더하는 동시에 그 전부를 잔류 부담에도 넣었다.
v3에서는 `InteractionLoad`로 **새 부담을 쌓는 작업량**과 **실제로 점수를 매길 즉시 비용**을 구분한다.

```text
누적 작업량 = 동작 비용 + InteractionLoad × 간섭 비용
즉시 비용 = 동작 비용 + 간섭 비용
반복 비용 = 즉시 비용 × RepeatGain × (잔류 부담 / LoadLimit)²
```

α가 0이어도 즉시 간섭 비용은 남는다. 과거 부담도 회복 전에는 남아 있으므로,
새 부담을 쌓지 않는 구간에서도 해당 부담에 따른 반복 비용이 발생할 수 있다.
전체 구간과 부분 구간은 각각 같은 두 rate로 적분하며 구간 분할 수에 의존하지 않는다.
즉시 비용과 행렬은 변경하지 않았고, 반복 보정 강도 4도 유지했다.

LN 없는 기준 난이도는 53.4226이며, LN A + taps B의 동작 48 / 즉시 간섭 21.6은 모든 비율에서 같다.

| α | 반복 비용 | 난이도 | 기준 대비 증가 |
|---|---:|---:|---:|
| 1 (기존) | 131.7509 | 80.5316 | 50.74% |
| 0.5 | 119.4645 | 75.5211 | 41.37% |
| 0.25 (새 기본값) | 113.0682 | 72.8762 | 36.41% |
| 0 | 107.1874 | 70.5269 | 32.02% |

기본 0.25는 실험용 선택이지 인체 측정에 맞춘 값은 아니다. α=1에서 기존 값이 재현되는지,
낮출수록 반복 증폭만 줄어드는지, 네 비율 모두 AB↔AC > AB↔DE가 유지되는지 테스트했다.
새 6초 chord 비교에서 AB↔AC는 90.5329, AB↔DE는 62.0639다.
시간은 그림에서 아래→위로 증가한다.

`internal/difficulty/load.go`는 누적 work와 즉시 demand를 분리한다. 검증은
`internal/difficulty/load_test.go`와 `cmd/poc/difficulty/interaction_test.go`에 있다.
[v3 비교 보고서](../../../artifacts/08-difficulty/interaction-load/report.md)에 비율별 결과와 원본 채보를 보존했다.

## 반복 가산 상한 축소

v4는 `RepeatGain` 기본값을 4에서 0.5로 줄인다. 속도 압축은 이미 동작 비용에 반영되므로,
반복 이력은 보조 항목으로 남긴다. 최대 가산은 기존 동작·간섭 비용의 400%에서 50%로,
최대 배수는 5배에서 1.5배로 내려간다. 오투잼 원본 레벨은 계산에 사용하지 않는다.
0.5는 과도한 증폭을 제한하기 위한 선택이며, 체감 난이도에 맞춘 측정값은 아니다.

부담을 쌓고 회복하는 식, 시간 압축, 간섭 행렬과 정확한 구간 적분은 유지한다.
같은 손가락 집중 > 손가락 교대, 휴식이 길어질수록 차이 감소, 같은 손 LN의 간섭도 유지된다.
각 200ms 창의 반복 비용이 기초 비용의 절반 이하인지, 전체 가중 난이도도 반복을 끈 값의
1.5배 이하인지 40/100/200/800ms chord·trill을 1배속과 2배속에서 검증한다.

`Out of Control / Hard` (`o2ma104.ojn`, 551 tap)의 1배속 재계산:

| 설정 | 가중 난이도 | 표시값 | 가중 합에서 반복 비용의 비중 |
|---|---:|---:|---:|
| 이전 가산 상한 4 | 278.3684 | 27.8 | 70.3% |
| 현재 가산 상한 0.5 | 109.8414 | 11.0 | 20.8% |
| 반복 비용 제거 | 87.5610 | 8.8 | 0% |

1.5배속은 21.4, 2배속은 33.5다. 반복 비용이 달라지면 창 순위도 다시 정렬되므로,
이전 가중 합의 반복 항목만 8로 나눈 결과와 전체 재계산 결과는 다를 수 있다.

현재 200ms chord 비교는 AB 반복 50.0674 > AB↔AC 46.5087 > AB↔DE 42.9501이다.
같은 입력량에서 집중 부담은 남지만 주된 점수가 되지 않는다. LN A + taps B는 32.4604,
해제된 A + taps B는 22.7819이며, 다른 손 LN의 추가는 같은 예시 행렬에서 비용을 만들지 않는다.

`difficulty.Model`을 `finger-motion-v4-poc`로 바꿔 이전 모델의 1배속·배속 캐시를
다음 곡 목록 스캔에서 모두 재계산한다. 캐시 교체도 `internal/songselect/ratings_test.go`로 검증한다.
