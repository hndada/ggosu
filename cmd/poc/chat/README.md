# 디버그 대화 발생기

가상 참가자들이 실제 WebSocket으로 방에 들어와 돌아가며 채팅한다.
서버가 지정한 순번·닉네임·시각과 기존 `chat`/`chat_history` 경로를 그대로 사용하므로
웹 곡 선택창·대기실·네이티브 플레이의 채팅을 같은 대화로 확인할 수 있다. 소리는 발생시키지 않는다.

저장소 루트에서 터미널 두 개로 실행한다.

```powershell
# 첫 번째 터미널: 기존 멀티 서버
go run ./cmd/multi

# 두 번째 터미널: DEBUG 채팅 방 생성, 3명이 2초마다 대화
go run ./cmd/poc/chat
```

데스크톱의 멀티플레이에서 `ws://127.0.0.1:8090/ws`에 접속하거나
브라우저에서 `http://127.0.0.1:8090/`를 열고 **DEBUG 채팅** 방에 참가한다.
출력의 `room=...`은 실제 방 ID다. 기본은 Ctrl+C까지 계속 발생하며, 종료하면 봇들이 퇴장한다.
새 DEBUG 방에서는 봇이 방장이므로 게임 시작을 검증하려면 사람이 만든 방에 아래처럼 참가시킨다.

```powershell
# 사람이 방장인 기존 방에 참가: 플레이/관전 중에도 대화가 계속된다
go run ./cmd/poc/chat -room 실제방ID

# 속도와 참가자 변경 (전체 대화 간격, 이름에 DEBUG 표시 권장)
go run ./cmd/poc/chat -room 실제방ID -names 'DEBUG 민수,DEBUG mint,DEBUG Sora' -interval 400ms

# 암호 방 / 유한 실행 (전송 ack 20건을 받은 후 봇 퇴장)
go run ./cmd/poc/chat -room 실제방ID -password '방비밀번호' -count 20
```

`-server`로 서버를 바꿀 수 있다. 봇도 방 정원에 포함되며 1~7명까지 지정한다.
각 봇의 전송 간격은 최소 1100ms로 제한해 서버의 5초당 5건 제한을 지킨다.
방이 가득 찼거나 암호가 틀렸거나 연결/ack가 실패하면 이유를 출력하고 모든 봇 연결을 정리한다.
봇은 채보를 보유하지 않은 대기자로 참가하고 선택·준비·시작·점수 제출은 하지 않는다.

짧은 한글/영문, 이모지, 긴 닉네임, 긴 문장, 여러 줄, HTML처럼 보이는 텍스트,
최대 300자 메시지까지 10개 샘플을 반복한다. 실제 방 대화에 추가되므로 디버그 방을 권장한다.

확인할 동작:

- F8 접기/펼치기와 접힌 동안 읽지 않은 메시지 개수.
- 이전 대화를 읽는 동안 스크롤 유지, 웹의 `최신으로`, 네이티브의 휠 이동.
- 접기/펼치기·경기 상태 변경 중 초안과 대화 유지.
- 늦게 참가한 클라이언트의 최근 12건 이력, 한글/줄바꿈/긴 메시지 표시.
- 네이티브 플레이에서 필드를 가리지 않는 채팅과 입력 중 플레이 키 분리.

```powershell
go test ./cmd/poc/chat
go vet ./cmd/poc/chat
go build -o build/poc/chat.exe ./cmd/poc/chat
```
