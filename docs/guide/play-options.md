# 노트 분포·최고 기록 비교·Mods·Time Rate

Wails는 옵션 선택·채보 분석·결과 비교를 맡고, Ebitengine은 변형한 채보의 입력·판정·오디오·화면을 처리한다.
같은 선택·결과 UI를 브라우저에서도 사용한다. 원본 채보와 내용 해시는 바꾸지 않는다.
곡 선택창의 '게임 모드'(F3)에서 일반/Auto를, '모드'(F1)에서 노트 배치·Time Rate·Pitch를 고른다. 키·스크롤·화면·오디오는 '환경 설정'(F10)에서 바꾼다.

## 노트 분포

곡 선택과 결과 화면에 원본 채보의 시간별 노트 시작 밀도, 구간 내 동시 LN 최댓값,
원본 레인별 시작 수를 표시한다. 마우스를 올리면 구간별 수치를 볼 수 있고, 펼친 표에서도 읽을 수 있다.

- NPS = (Tap + LN 시작 + Lift) / 구간 길이(초). LN과 roll은 시작을 한 번 센다.
- 동시 LN은 hold·roll의 유지 구간 `[시작, 끝)`을 겹쳐 센다. 같은 시각의 종료와 시작을 중복 집계하지 않는다.
- 지뢰는 따로 집계해 요약·구간 표·툴팁에 표시하고, Fake는 제외한다.
- 기준은 원곡 1배속 오디오 시간축이다. 음수 시작을 포함하고 Time Rate·오프셋·표시용 변속에 따라 그래프를 바꾸지 않는다.
- 기본은 1초 구간이며 긴 채보는 구간을 늘려 최대 600개로 제한한다. NPS는 해당 구간의 평균이며 마지막 구간도 같은 길이를 사용한다.
- 끝 시각의 노트 시작을 놓치지 않도록 경계에 구간을 추가할 수 있다. 그래프 범위에는 마지막 구간의 빈 시간이 포함될 수 있다.

LN 끝 판정은 노트 시작 수에 포함하지 않는다. 예를 들어 데모의 시작은 12개지만 LN 끝을 포함한 판정은 14개다.
노트 밀도와 동시 LN은 난이도·실제 키 입력 횟수의 추정값이 아니다.
분석은 선택 시 수행하며 플레이의 Update/Draw에서 채보를 다시 분석하지 않는다.

## 최고 기록 대비 변화

이전 최고 점수 기록 하나를 기준으로 점수·정확도(%p)·최대 콤보·KOOL/COOL/GOOD/MISS의 변화량을 표시한다.
현재 기록 자체를 제외하고 현재 결과 시각 이전의 기록만 비교한다. 점수가 같으면 최대 콤보가 높은 기록을 기준으로 한다.

비교 조건은 같은 원본 채보 해시·판정 규칙, 일반 플레이·완주·초기 1배속·도중 배속 변경 없음이다.
점수는 [110만점 규칙](score.md)의 새 버전 2 기록끼리 비교한다. 이전 버전 1의 점수는 목록에 표시하되 최고 비교에서 제외한다.
배치 변경 없음·Mirror·Random·Mirror+Random은 분리하며, 변형 배치는 실제 레인 매핑이 같아야 한다.
Random seed가 달라도 실제 매핑이 같으면 같은 조건이다. 개인 스크롤·오프셋·음량 설정은 최고 기록을 나누는 조건이 아니다.
첫 기록은 비교 대상이 없다고 표시하고, Auto·리플레이·배속 연습·미완주는 비교에서 제외한다.
양수·음수 변화량을 그대로 표시하므로 MISS가 줄었을 때는 음수다.

## Mods

게임 모드·체력 모드·Pitch는 버튼으로 선택한다. Mirror와 Random은 각각 켜고 끄는 독립 버튼이며 함께 선택할 수 있다. 둘 다 끄면 배치 변경 없음이다.
Mirror는 같은 플레이어 그룹 안의 일반 키 순서를 뒤집고, Random은 같은 그룹 안의 일반 키를 섞는다.
함께 켜면 같은 seed의 Random 배치를 좌우 반전한다. 저장 값과 CLI의 `-mod` 값은 `mirror+random`이다.
UI는 [osu!의 모드 선택 화면](https://osu.ppy.sh/wiki/en/Gameplay/Game_modifier)의 개별 버튼·약어 표기를 참고한다. 선택된 버튼은 강조색과 ON 표시를 함께 사용하며 F1은 노트 배치, F3은 게임 모드 버튼에 포커스를 둔다.
스크래치는 원래 위치에 남으며 플레이어 그룹 사이로 노트를 이동시키지 않는다.
레이아웃 정보가 없는 채보는 모든 레인을 일반 키 한 그룹으로 취급한다.
현재 SM 변환기는 조작 타입별 레이아웃을 저장하지 않으므로 SM에는 이 한 그룹 규칙을 적용한다.
BMS와 레이아웃이 지정된 GGC는 저장된 스크래치·그룹 정보를 사용한다.

곡 전체에 하나의 레인 순열을 적용한다. 노트별로 다시 섞지 않으며 LN의 시작·끝·음원·시각을 유지한다.
새 Random 플레이는 새 uint32 seed를 만들고, Wails 결과의 재시작은 같은 seed와 초기 Time Rate를 재사용한다.
새 seed가 반드시 다른 실제 배치를 만든다는 보장은 없다. CLI의 `-seed` 기본값은 0이며 직접 지정하면 재현할 수 있다.

리플레이에는 seed와 원본→현재 레인 매핑을 함께 저장한다. 재생은 저장된 매핑을 사용하며 새로 난수를 뽑지 않는다.
입력 이벤트는 이미 변형된 목적지 레인 번호이므로 재생 시 이벤트를 다시 변형하지 않는다.
Mods 없는 기존 기록은 배치 변경 없음으로 읽는다. 잘못된 순열, 스크래치 이동, 그룹 교차, 잘못된 Mirror 매핑은 거부한다.

## Visibility

모드(F1)의 Visibility에서 Hidden·Fade In·Cover·Flashlight 중 하나를 선택한다.
켜진 항목을 다시 누르면 OFF가 된다. Mirror·Random·Time Rate·Pitch와 함께 쓸 수 있다.

| 효과 | 표시 |
|---|---|
| Hidden (HD) | 판정선에 가까워지면 노트가 서서히 사라진다. |
| Fade In (FI) | 위쪽 노트가 숨겨지고 아래로 내려오면서 서서히 나타난다. |
| Cover (CO) | 판정선까지의 레인 상단 절반을 가린다. |
| Flashlight (FL) | 레인 중앙의 좁은 가로 영역에서만 노트를 보여 준다. |

Hidden·Fade In은 콤보 0~480에 따라 가림 범위가 커지며 MISS로 콤보가 끊기면 줄어든다.
가림은 현재 스킨·판정선 높이에 비례한다. 롱노트 머리·몸통·꼬리에도 적용하고,
판정선·키·입력 피드백·HUD에는 적용하지 않는다. osu!mania의 기본 효과를 참고한 ggosu 구현이며,
osu!의 모든 세부 옵션·쉬는 구간 연출을 그대로 재현하는 것은 아니다.

선택은 로컬 설정과 기록의 `mods.visibility`에 저장하며 재시작·리플레이에서 복원한다.
기존 기록은 OFF로 읽는다. 최고 기록과 결과 비교는 같은 Visibility끼리 구분한다.
점수 배율·판정·음원·원본 채보 해시는 바꾸지 않는다. 기본 배치 달성 표시는 Visibility OFF 기록으로 계산하며
임시 PP 계산에서도 Visibility 기록을 제외한다. 멀티플레이에서는 방장의 효과를 공통 조건으로 사용한다.
CLI는 `-visibility hidden|fadein|cover|flashlight`를 사용하며 기본값은 OFF다.

참고: [Hidden 구현](https://github.com/ppy/osu/blob/master/osu.Game.Rulesets.Mania/Mods/ManiaModHidden.cs),
[Fade In](https://github.com/ppy/osu/blob/master/osu.Game.Rulesets.Mania/Mods/ManiaModFadeIn.cs),
[Cover](https://github.com/ppy/osu/blob/master/osu.Game.Rulesets.Mania/Mods/ManiaModCover.cs),
[Flashlight](https://github.com/ppy/osu/blob/master/osu.Game.Rulesets.Mania/Mods/ManiaModFlashlight.cs).

## 체력

모드(F1)의 체력 옵션에서 OFF 또는 시작 단계(1·2·3단)를 선택한다. 기본은 3단 시작이며 게임 오버 없이 계속 진행한다.
각 단계는 처음부터 같은 판정을 각각의 회복·감소량으로 계산한다. 1·2·3단은 beatoraja의 ASSIST EASY·HARD·EX-HARD 게이지를 고정값으로 옮긴 것이며 판정별 값은 [HUD 설계](../design/hud.md#체력과-ghost)에 있다. GOOD으로 체력이 줄어드는 것은 3단뿐이고, 어느 단계도 GOOD만으로 0%가 되지 않는다. 현재 단계가 0%가 되면 3→2→1단으로 내려가며,
새 단계는 그동안 계산된 체력을 이어받는다. 풀피로 초기화하거나 회복으로 상위 단계에 돌아가지 않는다.
1단이 0%가 되어도 계속 판정하며, 이후 KOOL·COOL로 다시 회복할 수 있다.

게임 오버 기준은 '계속 진행' 또는 '1·2·3단 0%' 중에서 선택한다. 선택한 단계가 0%가 되면 기존 종료 전환을 거쳐 결과 화면으로 돌아온다.
시작 단계보다 높은 게임 오버 단계는 선택할 수 없으며 시작 단계를 낮추면 기준도 해당 단계까지 내려간다. OFF에서는 게임 오버 기준이 적용되지 않는다.
시작 단계와 게임 오버 기준은 로컬 설정에 저장하며, 체력 HUD는 현재 단계와 정확한 백분율을 표시한다.
기록·리플레이에 단계별 체력과 시작·종료 기준을 저장한다. 기존 단일 체력 리플레이는 저장 당시처럼 해당 단계 0%에서 종료한다.
CLI는 `-health 3 -health-fail 0`이 기본이며, `-health 0`으로 끄고 `-health-fail 2`로 2단 0% 게임 오버를 지정한다.

## 이벤트: O2Jam

모드(F1)의 **이벤트** 칸에 있는 O2 버튼은 누를 때마다 OFF → EASY → NORMAL → HARD → OFF로 바뀐다. 켜면 판정·체력·콤보를
[open2jam](https://github.com/open2jamorg/open2jam/tree/11384b3ca957828ae66a72c9e28edd42c97952d5)의 기본 방식으로 바꾸며, 위 체력 옵션과 게임 오버 기준은 적용하지 않는다.
KOOL·COOL·GOOD·MISS는 O2Jam의 COOL·GOOD·BAD·MISS에 대응한다.

- 판정(`BeatJudgment`): 박자 거리 ÷ 0.664가 0.2 이하 KOOL, 0.5 이하 COOL, 0.8 이하 GOOD. 0.8을 넘는 입력은 노트를 소비하지 않고, 노트가 0.8박을 지나면 MISS다. 120 BPM에서 ±66·±166·±266 ms이며 BPM이 빠를수록 좁아진다. 정지(STOP) 동안에는 박자가 흐르지 않는다. 롱노트 끝도 같은 범위로 판정한다.
- 체력(`Render.java`): 최대 24000(EASY)·36000(NORMAL)·48000(HARD)으로 시작한다. KOOL +96(HARD +48), COOL 0, GOOD −240, MISS −1440. 0이 되면 바로 게임 오버다.
- 콤보: GOOD도 콤보를 끊는다. 점수는 110만점 규칙 그대로다.
- 알약(PL 버튼, O2가 켜졌을 때만): KOOL 15개마다 1개(최대 5개)를 얻고, 다음 GOOD 하나를 COOL로 바꾼다. COOL·GOOD·MISS는 KOOL 연속 수를 초기화한다. 체력 바 위에 다섯 칸으로 표시한다.

체력 HUD는 단계 대신 EASY·NORMAL·HARD를 표시하고, 타이밍 미터는 현재 BPM의 GOOD 범위를 양 끝으로 쓴다.
기록·리플레이는 `mods.o2jam`·`mods.pills`와 `health_gauge: 2`로 저장하며 서버 검증도 같은 규칙으로 다시 계산한다.
일반 판정과 범위가 달라 최고 점수·클리어 램프·pp에서 제외하고, 기록 목록의 최고 기록은 같은 O2Jam 조건끼리 비교한다. 멀티플레이에는 적용하지 않는다.
CLI는 `-o2jam easy|normal|hard`와 `-pills`다.

## Time Rate

모드(F1)의 Time Rate 버튼과 슬라이더로 1.0·1.1·1.25·1.5배를 선택한다. '임의 설정'을 켜면 0.5~2.0배 슬라이더(0.01 단위)와 직접 숫자 입력을 사용할 수 있다. 위쪽 배율 버튼도 같은 스케일의 위치에 표시하며, 1.0배는 범위의 1/3 지점에 놓인다. 임의 설정을 끄면 가장 가까운 기본 배율을 적용한다. 저장된 임의 배율은 다음 실행에도 그대로 복원한다.
프리뷰·네이티브·웹·멀티플레이에 같은 범위를 적용한다. 일반 플레이·Auto·멀티플레이 도중에는 변경할 수 없으며 리플레이에서만 F7로 바꿀 수 있다. Edit는 별도 편집 재생 속도를 사용한다.
노트·게임 시계·음원 재생을 같은 비율로 진행한다. Pitch On은 기존 리샘플링 방식으로 음높이도 바꾸고,
Pitch Off는 WSOLA로 오디오 길이를 바꿔 원래 음높이를 유지한다. 선택한 옵션은 프리뷰·플레이에 함께 적용한다.
Pitch 옵션은 기록에 저장하며 재시작·리플레이에서도 유지한다. 기존 옵션 없는 기록은 On으로 읽는다.
CLI는 `-pitch=false`로 원래 음높이를 유지한다. 신호의 길이·주파수·스테레오 위상은 테스트했으며,
복잡한 음악과 극단적인 배속에서는 시간 늘이기 특유의 음질 변화가 있을 수 있다.
알고리즘 근거: [WSOLA 논문](https://www.isca-archive.org/eurospeech_1993/roelands93_eurospeech.html).
속도 모드에서는 Time Rate가 올라가면 실제 화면의 스크롤도 같은 비율로 빨라진다. 기준 노출 시간 모드에서는 현재 배속에 맞춰 노트 간격을 보정해 기준 노출 시간을 유지한다.

입력과 리플레이 시각은 항상 `game-1x`다. 배속이나 정지는 저장된 입력 좌표를 재스케일하지 않는다.
기록의 `rate`는 초기 배속이며, 1배속 외 시작 또는 F7 사용은 `practice`로 표시한다.
Wails 재시작은 초기 배속을 유지하고 리플레이 보기는 기록의 초기 배속을 사용한다.
도중 F7 변경 이력과 일시정지 길이를 영상처럼 재현하는 기능은 포함하지 않는다.
게임 모드·노트 배치·Time Rate·Pitch는 값을 바꾸면 로컬 설정 파일에 자동 저장하고 다음 실행에서 복원한다.
스크롤·키 배치·볼륨·오프셋·화면·스킨 설정도 함께 보존한다. 숫자 설정은 Enter 또는 입력창을 벗어날 때 저장한다.
스크롤 속도는 osu!lazer mania와 같은 1~40이며 키 수별 보정은 -39~39 범위다. 실제 적용값은 1~40으로 제한한다.
플레이 중 PgUp/PgDn으로 바꾼 스크롤 속도도 종료 후 저장하며, 0점 플레이에도 적용한다. 리플레이에서 바꾼 값은 전역 설정에 반영하지 않는다.

로딩 완료 후 기본 시작 대기는 실제 시간 0.25초다. 채보의 음수 시각 오디오·노트가 있으면 이를 재생할 시간을 확보한다.
음악·노트의 시각이나 리플레이 좌표는 바꾸지 않는다. 일시정지 재개는 기존 3초 카운트다운을 사용한다.
설정 → HUD에서 Argon·Triangles·Classic·Circles 스킨을 미리보기로 선택하며, 선택한 스킨은 다음 실행에도 유지된다.
이전 범위에서 저장한 기록은 조회할 수 있지만, 초기 배속이 0.5~2.0배를 벗어난 리플레이는 재생할 수 없다.

```powershell
# 같은 seed로 여러 번 실행하면 같은 Random 배치
go run ./cmd/game -chart songs/demo/demo.osu -auto -mod random -seed 123 -speed 1.5
go run ./cmd/game -chart songs/demo/demo.osu -auto -mod mirror
```

## 해상도

환경 설정(F10) → 화면 → 해상도에서 1024×640, 1280×720, 1366×768, 1600×900(기본),
1920×1080, 2560×1440, 3840×2160을 선택한다. 창 모드에서는 메뉴 크기가 즉시 바뀌고,
다음 플레이 창에도 같은 크기를 적용한다. 선택은 재실행 후에도 유지한다.
전체화면·테두리 없음은 모니터 크기를 사용하며, 창 모드로 돌아오면 저장된 해상도를 적용한다.
크기는 Windows 배율이 적용되는 논리 픽셀 기준이다. CLI는 `-resolution 1280x720`처럼 지정한다.

## 연습 구간

모드(F1)의 '연습 구간'에서 선택한 채보의 노트 밀도 그래프를 드래그해 구간을 정한다. 조작은 레벨·길이 필터의 범위 창과 같다.
양 끝을 끌어 넓히거나 줄이고, 가운데를 끌어 옮기며, 더블클릭하면 해제한다. 구간 단위는 그래프 한 칸(보통 1초)이다.
구간은 채보별로 기억하며 지정 중에는 하단의 F1 버튼이 '모드 · 구간'으로 바뀐다.

플레이는 구간 시작 1초 전(실제 시간)부터 시작해서 구간 안에서 시작하는 노트만 판정한다. 구간 끝을 넘는 LN은 끝까지 판정한다.
구간 밖 노트의 키음은 배경음으로 재생하고, 구간 끝 이후에 시작하는 오디오는 재생하지 않는다([beatoraja PracticeModifier](https://github.com/exch-bms2/beatoraja/blob/master/src/bms/player/beatoraja/pattern/PracticeModifier.java)와 같다).
마지막 판정 1초 뒤나 게임 오버 시점에 구간 시작으로 돌아가 반복하며, 일시정지 메뉴에서 나갈 때까지 계속한다.
HUD 편집처럼 기록·리플레이를 남기지 않는다. 데스크톱의 일반 플레이·Auto에서만 쓰며 리플레이·멀티플레이에서는 무시한다. 웹 플레이에는 아직 없어 항목을 숨긴다.
CLI는 `-section-start 42s -section-end 1m5s`로 지정한다.

## 검증

아래 실제 플레이 점수는 110만점 규칙 도입 전의 검증 기록이다. 현재 점수 계산과 호환성 검증은 [점수 규칙](score.md)을 참고한다.

`go test ./...`, `go vet ./...`, `node --test songlist/search.test.js songlist/analysis.test.js`.
스크래치·그룹 보존, 동일 seed 재현, 저장된 매핑 우선, 원본 해시·LN 시각 보존,
Mods·오프셋 리플레이 점수 일치, 시간 경계·최대 600개 구간·LN 지속,
현재/미래 기록 제외·비교 조건·정확도 %p 변화 등을 검사한다.

실제 Wails 백엔드 개발 화면에서 그래프(데모 12개 시작·구간 평균 최대 3 NPS·동시 LN 최대 2개),
범위 밖 Time Rate의 플레이 차단, Random 1.5배속 Auto·같은 배치 재시작·저장 리플레이의
동일 매핑과 14 KOOL·14,000점을 확인했다. Mirror 2배속 Auto도 같은 점수로 완주했다.
일반 플레이 두 번으로 첫 기록 안내와 이전 기록 대비 변화량 표를 확인했다. 입력하지 않은 두 실행은 모두 0점이므로 UI 변화량은 0이며,
양수 점수·정확도(%p) 변화와 음수 판정 개수 변화는 테스트의 통제된 점수로 확인했다.
새로고침한 결과 화면에서도 분포를 불러오는 동작을 확인했다.
실제 웹 실행기의 Random 1.5배속 Auto도 14 KOOL·14,000점으로 완주했고 콘솔 오류는 없었다.
Go 테스트·정적 검사·JS 테스트·Wails 및 WASM 빌드가 통과했다.
