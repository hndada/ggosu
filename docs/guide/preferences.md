# 환경 설정

Wails에서 편집·저장·초기화하고 다음 플레이를 시작할 때 설정을 전달한다.
파일은 실행 파일 옆 `data/settings.json`이다. 플레이 중 볼륨 변경은 마지막 입력 500ms 뒤 저장하며, 그 전에 종료하면 종료 시 저장한다.
오프셋·키 수별 프로필·오디오·표시·플레이 옵션은 같은 파일에 저장하되 각각 저장할 때 다른 항목을 유지한다.
모드(F1)의 게임 모드·노트 배치·Time Rate·Pitch도 변경하면 자동 저장하고 재실행 시 복원한다.

## 1. 키 바인딩

환경 설정(F10, 타이틀의 "환경 설정")은 Quaver 옵션 메뉴처럼 왼쪽 탭(키 바인딩·스크롤·화면·HUD·오디오)으로 나뉜다.
항목마다 "이름 | 값" 한 줄이며, 값을 바꾸면 바로 저장한다. 숫자 칸은 Enter를 누르거나 칸을 벗어날 때, 슬라이더는 놓을 때 저장한다.

환경 설정의 키 수 선택은 1K~10K를 지원한다. 키 바인딩 탭 상단에서 키 수를 고르면 해당 레인을 실제 플레이 순서대로 나란히 표시한다. 각 레인 중앙에는 현재 할당된 키가 보인다.
레인을 클릭하면 그 레인의 키만 변경하고 바로 저장한다. 입력 대기 중인 레인 위에는 아래쪽 화살표가 표시된다. 키보드로 레인에 포커스를 옮긴 뒤 Enter 또는 Space를 눌러도 변경할 수 있다.
"전체 키 순서대로 입력"은 레인 1부터 마지막 레인까지 받는다. 전체 입력 중에는 Backspace로 이전 레인으로 돌아갈 수 있으며, 마지막 레인까지 입력했을 때 한 번 저장한다.
저장하지 않은 키 수는 hndada/gosu의 기본 키를 쓴다(4K `D F J K`, 6K `S D F J K L`, 7K `S D F Space J K L`, 8K `A S D F Space J K L`, 9K는 8K에 `;`, 10K `A S D F V N J K L ;`). 레인 구성이 없는 8K 채보는 hndada처럼 7K와 왼쪽 스크래치로 보고 맨 왼쪽 레인을 스크래치 레인으로 그린다. BMS는 채보의 스크래치 레인을 따른다. 이렇게 하면 스크래치 레인이 가장자리 키(8K는 A, 5+1은 S)에 자동으로 놓인다.
입력 중 Esc를 누르면 변경을 취소하고 이전 키 배치를 복원한다. Tab으로 입력 영역을 벗어나거나 키 수를 바꾸거나 설정 창을 닫아도 미완료 입력은 버린다.
A–Z, 0–9, Space, Semicolon을 지원한다. Tab은 포커스 이동용이며 P·Escape·F6·F7·PageUp/Down은 예약 키다.
중복·지원하지 않는 키·예약 키는 백엔드에서도 거부하고 기존 파일을 유지한다.
프로필 초기화는 해당 키 수의 키와 스크롤 보정만 기본값으로 되돌린다. 공통 스크롤·노출·변속 값은 유지한다.

레인 배치와 입력 확인 영역(`scenes/settings/keytest.js`, 판정은 `preferences/keytest.js`)으로 바인딩을 확인한다.

- 레인 버튼이나 확인 영역에서 키를 누르는 동안 할당된 레인이 켜진다. 한 키가 여러 레인에 있으면 모두 켜진다.
- 확인 영역에서 할당되지 않은 키·예약 키·지원하지 않는 키를 누르면 그 이유를 알린다.
- 예약·미지원 키(Shift 등)는 할당하지 않고 이유만 알린다. 레인 하나를 변경할 때는 다른 모든 레인과의 중복을 검사한다. 전체 순서 입력에서는 이미 입력한 앞 레인과의 중복만 검사하므로 기존 배치를 재배열할 수 있다.
- 저장된 키에 중복이 있으면 해당 레인을 점선으로 표시하고 프론트엔드에서도 저장을 막는다.
- 동시에 눌린 물리 키 수와 최댓값을 보여 준다. 누른 키보다 최댓값이 작으면 키보드 동시 입력 한계다.
- 미니 테스트는 계단(1→N→1)과 8키 이하의 전체 동시치기 2회를 떨어뜨리고, 아래 선 기준 ±150 ms로 판정해 평균·편차를 알려 준다.
  소리 없이 화면만 보는 테스트라 결과를 오프셋에 자동으로 반영하지 않는다.

## 2. 스크롤 속도

스크롤 기준·스크롤 속도·기준 노출 시간·변속 반영은 모든 키 수가 함께 쓴다. 속도 모드는 osu!lazer mania의 스크롤 속도를 따른다. 범위 1~40, 기본값 8, 0.1 단위다. 속도 1은 lazer 기본 스테이지(화면 위 끝~lazer 기본 판정선)를 11485 ms에 지나가는 빠르기이며, 1280×720 기준 화면에서 약 52.5 px/s다. 이전 버전에 px/s로 저장된 속도·보정값은 이 비율로 환산해 읽는다.
스크롤 탭 아래 **키 수별 보정**에서 키 수마다 공통값에 더할 값(속도 모드는 속도 값, 노출 모드는 ms)을 정한다. 옆에 실제 적용값(`= 9.5`)을 보여 주며, 플레이에는 속도 1~40·100~5000 ms 범위로 제한한 합계를 쓴다.
PageUp/Down의 플레이 중 변경은 해당 실행·리플레이 기록에 반영하고, 끝나면 공통값을 그만큼 옮긴다. 그 키 수의 보정은 유지한다.
속도를 바꾸면 설정 창과 곡 선택의 PageUp/Down 안내에 기준 노출 시간을 ms로 함께 표시한다.
속도 모드에서는 곡 선택·플레이의 PageUp/Down으로 1씩, Alt+PageUp/Down으로 0.1씩 조절한다(lazer의 키 조절 간격 1). 설정창의 속도·보정 입력칸도 PageUp/Down·↑/↓는 1, Alt+PageUp/Down·Shift+↑/↓는 0.1씩 움직인다. 플레이 HUD는 설정창과 같은 속도 값으로 표시한다.
플레이 HUD의 EXPOSURE도 함께 갱신되며, PageUp/Down을 누를 때는 집중 HUD에서도 1.5초 동안 속도·노출 시간을 표시한다.
기준 스크롤 속도와 노출 시간은 채보의 절대 BPM에 독립적이며, 노출 시간은 현재 배속·스킨과 판정선까지의 높이·키 수별 보정을 반영한다. 이후 변속이나 정지 구간의 실제 노출 시간은 달라질 수 있다.

## 3. 기준 노출 시간·변속

기준 노출 시간 모드는 100~5000 ms, 기본값은 750 ms다. 현재 재생 속도를 사용하며 BPM에 영향을 받지 않는다.

```text
px/s = 레인 높이 × 1000 / (기준 노출 ms × 재생 속도)
표시 속도 비율 = max(0, 1 + 변속 반영 × (BPM ÷ 주 BPM × 원래 스크롤 배율 - 1))
```

주 BPM은 첫 타이밍부터 마지막 노트까지 가장 오래 유지된 BPM이다(lazer와 같은 기준). 변속 반영 범위는 0~2다. 0은 일정 스크롤, 1은 원래 스크롤 배율, 2는 변화량을 두 배 반영한다.
명시적인 Stop은 유지한다. 변속·정지 구간의 실제 노출 시간이 설정한 기준값과 같다는 뜻은 아니다.
재생 속도를 바꿔도 기준 노출 시간은 유지한다. 노출 모드에서 PageUp/Down은 기준 시간을 25 ms씩 조절한다.
표시용 타이밍 복사본만 바꾸며 판정·BGM·원본 채보·내용 해시는 유지한다.

프로필은 레인 리플레이에 저장하며 재생 시 저장 당시 키 표시·스크롤·노출·변속 값을 복원한다.
기존 프로필 없는 기록은 기본값 또는 현재 실행 옵션을 사용한다. 입력 시각은 기존처럼 원곡 1배속 시간축이다.

### 레인 커버

beatoraja의 SUDDEN+·HIDDEN+·LIFT를 따른다. 스크롤 탭에서 각각 켜고 끄며, 값은 판정선 위 레인 높이의 0~100%다.
기본값은 beatoraja `PlayConfig`와 같이 SUDDEN+ 20%·HIDDEN+ 10%·LIFT 10%이고 모두 꺼져 있다. 스크롤처럼 모든 키 수가 공유한다.

- SUDDEN+는 위에서, HIDDEN+는 판정선 위에서 노트를 가린다. LIFT는 판정선을 올린다.
- 가장자리는 osu!lazer `PlayfieldCoveringWrapper`처럼 필드 높이 25%의 그라데이션이며, 값이 바뀌면 반감 시간 25 ms로 따라간다.
- 기준 노출 시간 모드는 시작할 때 SUDDEN+ 아래 보이는 구간이 기준 시간이 되도록 속도를 정한다. 플레이 중 커버를 움직이면 속도는 그대로이고 보이는 시간만 바뀐다. PageUp/Down으로 기준 시간을 바꾸면 그때의 커버로 다시 맞춘다.
- 플레이 중 Shift+F4는 SUDDEN+를 켜고 끈다. F3/F4는 표시 속도를 높이고 낮춘다. ↑/↓는 1%, Ctrl+휠은 한 칸에 0.5% 움직인다. 휠만 굴리면 채팅을 스크롤한다.
- 조절 대상은 beatoraja와 같다. SUDDEN+가 켜져 있거나 LIFT·HIDDEN+가 모두 꺼져 있으면 SUDDEN+, 아니면 LIFT, 그다음 HIDDEN+다.
- 플레이 중 바꾼 값은 끝난 뒤 저장한다(리플레이 제외). 커버는 기록 비교 조건이 아니며 리플레이에 저장해 재생 때 복원한다.
- 가시성 Mod와 함께 켜면 같은 쪽에서는 더 많이 가리는 쪽을 쓴다.

## 4. 볼륨

마스터·음악·키음·재생 제어 효과음은 각각 0~100%다. 0은 음소거이며 명시적인 0을 기본값으로 덮지 않는다.
기본값은 마스터 100%, 음악 100%, 키음 100%, 효과음 50%다. 마스터는 모든 소리에 곱하며 음악·키음에는 원본 샘플 볼륨도 곱한다.
Alt+↑/↓는 선택한 볼륨을 5%씩 조절하고, Alt+←/→는 마스터·음악·키음·효과음을 순환 선택한다. 처음 누를 때부터 변경하고, 잠시 조작하지 않아 표시가 사라지면 다시 마스터부터 조절한다.
타이틀·곡 선택·결과·설정 창과 플레이·Auto·리플레이·일시정지·HUD 편집·멀티플레이 대기에서 사용할 수 있다. 재생 중인 소리는 되감거나 다시 시작하지 않고 즉시 바뀐다. 변경값은 자동 저장하고 플레이 종료 후 메뉴도 다시 읽는다.
스케줄된 배경 음원은 `Session.Music`, 노트 입력·홀드 종료 음원은 `Session.Sounds`로 분리한다.
효과음은 시작·일시정지·재개·완료의 짧은 합성 안내 소리다. 자체 볼륨·고정 피치·일시정지 정책을 사용한다.
음소거한 BGM도 끝까지 시간을 진행하므로 음량이 완주 시점을 바꾸지 않는다.

## 5. 플레이 화면·배경 표시

환경 설정[F10]의 **HUD 탭**에서 플레이 화면 섬네일로 스킨(Argon·Triangles·Classic·Circles)을 고르고, 기본·집중 모드를 고른다. 스킨 선택도 로컬에 저장된다. **HUD 편집**은 선택한 채보를 Auto로 반복 재생하며 바뀐 내용을 바로 보여 준다. 기본은 기존 곡 정보·콤보·점수·정확도·판정 개수·재생 설정·오차 미터를 표시한다.
집중은 노트·작은 진행률·플레이 종류·콤보·판정을 유지하고 상세 HUD와 측면 패널을 숨긴다.
같은 HUD 탭의 **노트 두께**는 스킨 기본 높이의 50~200%로 조절한다. 슬라이더를 놓으면 저장되어 다음 실행에도 적용되며, 탭 노트와 롱노트 머리·꼬리 높이를 함께 바꾼다. O2Jam의 기본 두께는 32px다. 레인 너비·판정 시각·점수·오디오는 바뀌지 않는다. CLI는 `-note-thickness 50..200`이다.
콤보와 판정은 기본적으로 레인 가운데에 표시한다. 같은 탭의 **시간 표시·콤보 위치·판정 위치**에서 각각 레인 가운데·레인 아래·왼쪽 HUD를 선택해 저장할 수 있다.
HUD 모드와 위치는 독립적이다. 일반 플레이와 Auto는 시작 전에 선택한 HUD를 유지하며, 리플레이에서만 F6으로 전환할 수 있다. 가운데 표시는 준비·일시정지·재개 카운트다운·완료 안내 중에는 숨긴다.
기본 HUD에서 아래 표시를 선택하면 오차 미터는 왼쪽 HUD의 비어 있는 영역으로 이동하여 콤보·판정과 겹치지 않는다.
위치 필드가 없는 이전 설정도 가운데를 기본값으로 사용한다. CLI는 `-combo-position center|below|left`, `-judgement-position center|below|left`다.
리플레이의 F6 전환은 다음 실행의 기본 설정을 덮어쓰지 않는다. 판정·점수·오디오·리플레이 시각에는 영향을 주지 않는다.
네이티브 CLI는 `-hud standard` 또는 `-hud focus`다. 웹은 같은 설정 화면을 사용하며 이 표시 설정을 origin별 localStorage에 보관한다.
HUD 필드가 없는 기존 설정은 기본 모드로 읽는다.

Esc로 정지 화면을 켜고 끈다(P도 지원한다). 정지하면 레인·HUD·채팅을 포함한 전체 화면에 dim을 적용하고 채보와 무관한 공통 pause 효과음을 효과음 볼륨으로 재생한다.
정지 화면의 Resume·Esc 또는 웹의 재개 버튼으로 3–2–1 후 재개한다. 카운트다운은 배속과 독립적인 실제 3초이며, 노트·판정 시간과 음악·키음은 정지 상태다.
카운트다운 중 Esc·P·일시정지 버튼 또는 포커스 이탈은 재개를 취소한다. 돌아온 뒤 명시적으로 재개해야 한다.
Retry는 같은 채보·Mods seed·선택 배속을 유지한 채 점수·입력 기록·리플레이 커서·오디오·HUD를 초기화하고 준비 시간부터 다시 시작한다. Quit으로 중단하고 곡 선택으로 돌아간다.
정지 화면의 버튼은 ↑·↓로 고르고 Enter로 실행한다. 정지할 때마다 Resume이 먼저 선택되며, 마우스를 버튼 위로 움직이면 그 버튼이 선택된다.
카운트다운 중 발생한 키 입력은 재개 후 판정으로 밀려들지 않는다. 길게 누른 키는 떼고 다시 눌러야 한다. 이미 누른 키는 기존 일시정지 정책에 따라 해제한다.
늦게 도착한 프레임은 재개 시각을 현재 프레임에 맞춰 게임 시간을 건너뛰지 않는다. 멀티플레이는 개인 정지·재시작·HUD·배속 변경 없이 기존 동기화를 유지하며 Esc는 퇴장이다.

곡 정보·모드·배속·스크롤·오프셋은 왼쪽 위, 실시간 비교는 레인 가운데, 점수·정확도·판정 개수는 오른쪽 위에 표시한다. 점수는 7자리 숫자로, 정확도는 백분율로 배경 위에 바로 표시하며 영역 박스를 그리지 않는다. 판정 개수는 KOOL·COOL·GOOD·MISS 색상 글자로 표시한다. HUD 편집에서 각 영역을 이동·확대할 수 있다.
곡 제목·메뉴는 Gmarket Sans, 점수·콤보·판정은 Chakra Petch Bold 기반의 Gosu Counter를 사용한다. 숫자는 고정폭으로 다듬어 네이티브 HUD와 웹 결과 화면에서 같은 형태·간격을 유지한다. 글꼴은 프로그램에 포함하며, 상세 설정·설명은 읽기 편한 일반 서체를 쓴다. [배포 출처·라이선스](../../internal/typeface/fonts/README.md)를 참고한다.
점수 숫자는 180ms OutQuint 트윈으로 현재 표시값에서 새 점수까지 올라간다. 연속 판정은 진행 중인 값에서 이어지며, 정확도·콤보·판정 집계는 즉시 갱신한다. 종료 시에는 정확한 최종 점수를 표시한다. 결과 화면은 0부터 최종 점수까지 650ms 동안 올라가고, 저장 기록을 열거나 모션 감소 설정을 사용하면 즉시 표시한다. 점수 계산·저장·서버 제출에는 애니메이션을 적용하지 않는다.
레인 오른쪽의 세로 게이지는 실제 점수 계산 상태인 Flow(0–50)·Precision(0–20)을 표시한다. 집중 HUD에서는 이 게이지와 보조 정보 패널을 숨긴다.
기본 중앙 배치는 큰 콤보 숫자를 레인 위쪽, 판정과 오차를 입력선 가까이에 표시한다. 콤보·판정 위치 선택은 그대로 적용한다. 시간은 독립 패널 안의 진행 막대 또는 원형 게이지로 표시한다.
오른쪽은 접고 펼칠 수 있는 채팅 서랍이다. 방 미연결 상태에서는 안내만 표시하며 실제 전송은 멀티 방에 연결했을 때 가능하다.
레인 키 바인딩은 최초 시작과 빠른 재시작의 준비 시간에만 표시하고, 플레이·정지·재개 카운트다운 동안에는 숨긴다. 플레이 제어 단축키를 상시 표시하지 않는다.
설정의 **시간 표시**에서 진행 막대·파이를 고른다. 이전 설정은 진행 막대가 기본이며 네이티브 CLI는 `-time-display bar|pie`다.

dim은 0~100%, 기본값은 75%다. 배경·스토리보드 위에 적용하고 레인·HUD는 그대로 둔다. 곡 선택 배경도 같은 dim을 따르며, 설정 창에서 슬라이더를 움직이는 동안 바로 바뀐다.
배경 이미지와 지원되는 스토리보드의 표시를 각각 켜고 끌 수 있다. 네이티브에서 숨긴 이미지 에셋은 로딩에서도 제외한다.
영상 디코딩·Loop/Trigger 등 미지원 명령을 새로 구현한 것은 아니다.
오디오·표시 설정은 전역이다. 리플레이의 시각 프로필은 복원하되 음량·배경 표시는 현재 설정을 사용한다.

## 검증

집중 HUD·재개 카운트다운 추가 후 Go 전체 테스트·vet, 프런트엔드 테스트 53개, Wails·WASM 빌드가 통과했다.
0.5·1·2배에서 3–2–1 동안 게임 시간이 고정되고, 재개 취소·포커스 이탈·늦은 프레임·카운트다운 중 배속 변경을 검사했다.
네이티브 기본/집중/카운트다운 렌더링에서 레인 표시와 점수·채보 불변성을 확인했다. 첫 GPU 프레임 이후 캡처하며, 레인이 누락된 캡처는 실패시킨다.
실제 웹의 HUD 저장·F6 전환·정지·3초 후 재개 뒤 데모 Auto 결과는 14 KOOL·MISS 0·1,100,000점이었다.
네이티브 캡처는 `artifacts/15-hud/scene-hud-focus.png`, `scene-countdown.png`에 있다.

아래 점수 숫자는 이전 점수 규칙에서 수행한 검증 결과다. 현재는 [110만점 규칙](score.md)을 사용한다.

- 키 수별 기본값, 중복·예약 키, 노출·변속 범위, 설정 재시작 유지·초기화·다른 설정 보존 테스트 통과.
- 변속 1에서 원래 위치와 일치, 0에서 일정 속도와 Stop 보존, 원본 해시 보존 확인.
- 음악·키음 이벤트 분리, 제어 효과음 생성, 0% 음소거값 저장, 숨긴 이미지 로딩 제외 테스트 통과.
- 실제 Wails 백엔드 개발 화면에서 예약 키 거부, 프로필·음량·표시 저장, 새로고침 유지, 초기화 확인.
- 실제 Ebitengine에 숫자 키·900 ms·변속 0·dim 0을 적용한 캡처 확인.
- 속도 220·변속 0.5·음량 분리·배경 숨김을 적용해도 14 KOOL·14,000점 유지.
- 테스트·정적 검사·Wails 및 WASM 빌드 통과. 주관적인 청감 품질·물리 장치 지연을 측정한 결과는 아니다.

웹은 HUD·배경 표시·오디오 설정을 origin별로 저장한다. 키 수별 프로필과 Wails 파일 저장 API는 데스크톱용이다.
