# 점수 서버 제출

데스크톱과 브라우저는 일반 플레이가 끝나면 로컬 기록을 먼저 저장하고 점수·리플레이를 서버에 제출한다.
점수가 있는 완주와 체력 탈락이 대상이다. Auto·리플레이 재생·도중 취소·이전 판정 규칙은 제외한다.
배속·Pitch·Mirror·Random·Visibility·오프셋·체력 조건은 기록과 함께 보존한다. 제출은 점수 배율을 바꾸지 않는다.

## 서버 실행과 주소

```powershell
build/bin/web.exe -addr 127.0.0.1:8080 -songs songs -scores data/scores
```

서버는 웹 플레이 서버와 같은 `cmd/web`다. `-scores`가 서버 저장 위치이며 기본은 `data/scores`다.
서버의 `-songs` 카탈로그에 원본 해시가 같은 채보가 있어야 검증할 수 있다.
API만 쓰더라도 현재 웹 서버 실행 명령은 `-wasm` 위치의 웹 빌드 파일을 요구한다.

데스크톱 기본 주소는 `http://127.0.0.1:8080`이다. 환경 설정(F10) → 온라인에서 서버 기본 URL을 바꾸고 저장한다.
빈 주소로 저장하면 자동 제출과 대기열 처리를 끈다. 브라우저는 현재 사이트의 같은 origin에 제출하며 빈 주소로 끌 수 있다.
원격 주소는 http/https를 지원하고 사용자 정보·쿼리·프래그먼트가 포함된 주소는 거부한다.

## 결과와 재시도

결과 화면은 제출 중·제출 완료·실패·꺼짐 상태를 표시한다. 실패나 꺼짐 상태에서 **점수 제출 재시도**를 누를 수 있다.
통신은 플레이 루프와 분리하며 요청은 10초 이내에 끝난다. 실패가 로컬 점수나 리플레이를 지우지 않는다.
데스크톱은 `data/submissions/`, 브라우저는 `ggosu:submission:<기록 ID>`에 전달 상태만 저장한다.
리플레이는 기존 로컬 기록을 사용한다. 기존 기록 전체를 한꺼번에 업로드하지 않는다.

대기·실패한 제출은 다음 실행·새 일반 플레이 종료·수동 재시도 때 처리한다.
브라우저는 네트워크가 다시 연결됐을 때도 재시도한다. 성공 상태 저장 전에 종료되더라도 서버의 중복 확인으로 두 번 저장하지 않는다.
앱 종료는 진행 중 HTTP 요청을 취소하고 작업자를 기다린다. 미완료 작업은 다음 실행에 남는다.
이미 대기 중인 건은 당시 서버와 닉네임을 사용한다. 수동 재시도는 현재 설정의 서버와 닉네임을 사용한다.

직접 게임 CLI를 실행할 때는 로컬 결과 저장과 제출 주소를 함께 지정한다.

```powershell
$recordID = [guid]::NewGuid().ToString('N')
build/bin/game.exe -chart songs/song/chart.osu -result "data/records/$recordID.json" -score-server http://127.0.0.1:8080 -name Player
```

CLI의 제출은 종료 후 한 번 시도하며 실패해도 지정한 결과 파일을 유지한다. 메뉴의 영속 대기열은 데스크톱 앱이 소유한다.

## API와 검증 범위

`POST /api/scores`에 `Content-Type: application/json`, `X-Gosu-Score: 1` 헤더를 사용한다.
본문은 `{ "player": "닉네임", "record": <piano.Record> }`이며 최대 32 MiB다.
서버는 현재 규칙·기록 형태·Mods·원본 해시를 확인하고 원본 채보에 오프셋·배치를 적용한 입력 리플레이로 판정·점수·체력·타이밍 통계를 다시 계산한다.
제출 결과와 다르면 422, 채보가 없으면 404, 다른 결과가 같은 기록 ID를 사용하면 409로 거부한다.
클라이언트의 `verification` 값은 신뢰하지 않는다.

새 기록은 디스크에 저장한 뒤 201과 `{ "id": "...", "received": "UTC 시각", "verified": true }`를 반환한다.
같은 기록을 다시 보내면 기존 접수 정보를 200으로 돌려준다. 서버 재시작 후에도 중복 확인과 접수 정보가 유지된다.

여기서 verified는 리플레이와 서버 계산의 일치를 뜻한다. 계정 인증·실제 사람 입력 확인·온라인 순위 집계는 별도 기능이다.
닉네임은 제출자가 제공하며, 이 구현으로 인증된 사용자 순위라고 주장하지 않는다.

## 코드

- `internal/server/scores`: 제출 HTTP 처리·서버 재계산·영구 저장·중복 확인.
- `internal/score`: HTTP 제출·접수 정보·제출 대상 정책.
- `internal/menu/submission.go`: 데스크톱 대기열·설정·종료·결과 상태.
- `preferences/submission.js`: 브라우저 대기열과 HTTP 제출.
- `internal/play/record.go`: 독립 CLI의 저장 후 제출.
