# 브라우저 플레이

웹은 별도 HTTP 서버에서 곡 목록·채보·에셋만 받는다. 판정, 노트 표시, 오디오,
스토리보드, Auto와 리플레이는 브라우저 안의 Go WebAssembly에서 실행한다.
`internal/play`의 공통 게임 상태와 Draw, `internal/chart`, `internal/piano`,
`internal/storyboard`, `internal/ui`를 네이티브와 공유한다. JavaScript로 판정을 다시 구현하지 않는다.

## 실행

```powershell
$env:GOMODCACHE = Join-Path (Get-Location) '.cache/mod'
$env:GOCACHE = Join-Path (Get-Location) '.cache/build'
pwsh -NoProfile -File scripts/buildweb.ps1
./build/bin/web.exe -addr 127.0.0.1:8080 -songs songs
```

브라우저에서 `http://127.0.0.1:8080`을 열면 gosu 홈페이지를 표시한다.
홈페이지에서 웹플레이를 누르거나 `/play`로 들어가면 데스크톱과 같은 타이틀을 표시한다.
싱글 플레이에서 채보·일반/Auto를 선택한다. 검색·채보 링크는 곡 선택으로 바로 들어간다.
게임과 음원 준비 후 **게임 안의 시작 버튼**을 누른다. 이 클릭으로 오디오를 시작한다.
Go 컴파일러에 맞는 `wasm_exec.js`는 빌드 스크립트가 함께 복사한다.
스크립트는 UI 소스를 내장한 `build/bin/web.exe`도 함께 빌드한다. 이미 실행 중인 서버는
종료한 뒤 다시 실행해야 새 HTML/CSS/JS를 제공한다. 브라우저는 UI 파일을 캐시에서 재검증한다.

## 홈페이지

`/`는 플레이 진입, 다운로드, 실제 곡별 채보 목록, 공지, 최근 브라우저 기록을 제공한다.
기능 설명·지원 포맷·설치·조작·기록 저장·유저 및 커뮤니티 안내는 별도 소개 페이지 `/about`에 모았다.
홈페이지도 앱의 `theme.css`를 불러와 글꼴과 색을 공유하고, `home.css`에서 웹페이지 배치를 정한다.
홈의 커뮤니티는 준비 상태만 짧게 표시한다. 계정·공개 유저 페이지·게시판의 계획은 소개에서 안내하며,
제작자는 별도 페이지가 아닌 유저 페이지로 통합할 계획이다.

홈 검색은 `/play?q=검색어`로 전달하며, `/play?chart=ID`는 해당 채보와 키 수를 선택한다.
`/play?chart=ID&edit=1`은 해당 채보의 편집 화면을 연다. `edit=1`만 있으면 채보 선택 후 Edit를 누르도록 안내한다.

Windows 개발 빌드는 `build/bin/gosu.exe`, `game.exe`, `songs/`를 준비한 뒤
`pwsh scripts/packdesktop.ps1`로 묶는다. ZIP은 `build/web/downloads/gosu-windows.zip`에 생성되며
`/download/gosu-windows.zip`으로 제공한다. `-wasm`을 바꾸면 그 디렉터리의 `downloads/`에서 찾는다.
파일이 없으면 홈에서 다운로드 준비 상태를 안내한다. 다운로드 디렉터리 전체를 공개하지 않는다.

레퍼런스와 구현·검증 범위는 [홈페이지 안내](../design/homepage.md)를 참고한다.

## 입력과 시간

- 기본 Update는 60TPS이고 Draw는 브라우저 프레임 스케줄을 따른다.
- `keydown`/`keyup`을 고정 큐에 받아 다음 Update에서 소비한다. 프레임 사이의 짧은
  누름·해제도 각각 보관한다. OS Raw Input 수신 스레드나 8,000Hz 폴링을 웹에서 실행하지 않는다.
- 물리 위치 `KeyboardEvent.code`를 사용하며 자동 반복 down을 제거한다.
- Space/PageUp/Down/F6/F7의 브라우저 기본 동작은 플레이 중에 막고 Ctrl/Alt/Meta 조합은 존중한다.
- Esc/P 정지·재개(3초 카운트다운), 정지 메뉴에서 빠른 재시작·곡 선택 복귀, PageUp/Down 표시 속도. F6 HUD·F7 배속은 리플레이에서만 가능하다. 게임 영역에 키보드 포커스를 준다.
- iframe 포커스 이탈 또는 문서 숨김은 자동 정지한다. 관측 시각에 시간축을 고정하여
  백그라운드 프레임 지연을 곡 시간으로 더하지 않는다. 돌아오면 재개 버튼 또는 Esc/P로 재개한다.
- 카운트다운 중 시간·음악·키음은 정지한다. 재개 전 포커스 이탈 또는 P·일시정지 버튼은 카운트다운을 취소한다.
- 환경 설정[F10]의 화면 탭에서 HUD·배경 표시를 저장할 수 있다. 표시 설정은 이 브라우저 origin에 저장하고 다음 플레이·리플레이에서 적용한다.
- 키 바인딩·스크롤·SUDDEN+/HIDDEN+/LIFT와 전체·채보별 타이밍 보정도 환경 설정에서 저장한다.
  스크롤 기준·레인 커버는 키 수마다 공유하고, 키와 스크롤·노출 보정값은 키 수별로 유지한다.
  플레이 중 바꾼 속도·커버는 종료 시 보존한다. 리플레이는 기록에 저장된 설정을 사용한다.
- 곡 목록의 계산 난이도와 Time Rate별 레벨은 데스크톱과 같은 계산기·캐시를 사용한다.
- 연습 구간[F1]은 노트 분포에서 선택한 구간을 반복하고 기록을 남기지 않는다.
- 시각은 브라우저에서 이벤트를 관측한 시각이다. 물리 키보드 발생 시각이나 네이티브 QPC와 같은 정밀도를 주장하지 않는다.

웹 오디오 플레이어는 100ms 버퍼를 사용한다. 현재 Oto worklet의 한 번 읽기가 약 42.7ms이므로
네이티브의 20ms 버퍼를 그대로 쓰면 읽기의 나머지가 무음으로 채워져 소리가 끊기고 음원 종료도 늦어진다.
네이티브는 기존 20ms 설정을 유지한다. 오디오 버퍼와 60TPS 입력 소비 주기는 서로 다른 설정이다.

## 기록과 파일

결과·레인 입력은 같은 원본 채보 digest와 `ggosu-keys-v1` 규칙으로 묶는다.
점수는 [110만점 규칙](score.md)을 사용하고 최고 기록은 새 결과 버전 2끼리 비교한다.
브라우저에서는 동일 출처의 localStorage에 저장한다. 일반/Auto/리플레이·배속·미완주는 구분하며
일반 완주 기록만 최고 기록에 포함한다. 리플레이는 기록 목록 또는 결과 화면에서 재생한다.

JSON 다운로드·JSON 보기·파일 가져오기를 제공한다. JSON 보기는 복사해서 파일로 보존할 수 있다.
가져온 기록은 Go 서버의 `record.Decode`로 검증하고, 재생 직전 Go WASM에서 채보 일치도 검증한다.
네이티브 `-result` 파일을 웹에 가져오고, 웹에서 내보낸 파일을 네이티브 `-replay-record`로 읽을 수 있다.
리플레이에 저장된 전체·채보별 오프셋도 복원한다. 웹의 수동 타이밍 보정은 브라우저에 저장한다.
자동 타이밍 보정은 데스크톱에서 제공한다.
곡 선택의 노트 분포·최고 기록 비교·Mirror/Random·Time Rate 옵션은 [모드](play-options.md)과 같다.
Mods의 실제 레인 매핑도 기록에 저장해 복원한다. 최고 기록 비교는 일반 1배속 완주와 같은 배치 조건으로 제한한다.
브라우저 저장이 거부되거나 용량이 부족하면 실패를 표시하고 현재 기록의 JSON을 보존한다.
localStorage 기록은 브라우저·프로필·포트 등 출처별이며 서버 디스크의 `data/records`와 자동 동기화하지 않는다.
닉네임·pp·오늘 입력한 키 수는 곡 선택 하단에 표시한다. pp와 입력 수는 검증된 브라우저 기록을 사용한다.
기록 다운로드·JSON 보기·가져오기는 환경 설정의 온라인 탭에 있다.
플레이 중 새로고침하면 아직 저장하지 않은 플레이는 중단된다.

## 서버 범위

`cmd/web`은 기본적으로 loopback에만 바인딩한다. 공개 배포를 자동으로 수행하지 않는다.
공통 UI는 `scenes`와 모듈 폴더에서 공유하고 브라우저 어댑터는 `internal/server/web/static/web.js`다.
네이티브 멀티플레이, 메들리 모드와 로컬 곡 폴더 추가는 데스크톱 기능이다.
원본 파서는 서버에서 실행되므로 기존 osu/OJN/BMS/SM 지원 범위가 동일하다.
목록 새로 읽기는 서버의 songs 폴더를 재검색한다. 현재 브라우저 로컬 곡 묶음 업로드나 순수 정적 사이트 내보내기는 제공하지 않는다.
서버는 곡 디렉터리 밖으로 벗어나는 에셋 경로를 거부하고 파일·버퍼 크기를 제한한다.
원본 게임별 호환성 제한은 [채보 안내](charts.md)의 표를 따른다.

## 검증

아래 14,000점은 이전 점수 규칙의 검증 기록이다. 현재 점수와 기존 기록 처리는 [110만점 규칙](score.md)을 따른다.

- 네이티브 및 웹 경로를 포함한 `go test ./...`, `go vet ./...`, JavaScript 문법 검사.
- `GOOS=js GOARCH=wasm` 빌드와 실제 in-app Chromium 브라우저 실행.
- osu Auto: 14 KOOL, MISS 0, 14,000점. 저장한 리플레이를 F7로 2배속에 바꿔도 같은 결과.
- 브라우저에서 약 1ms의 D/F/J/K 누름·해제 8개를 보존. 음수 리드인·중도 종료 기록까지 JSON으로 확인.
- 네이티브 SM 결과 파일 가져오기와 웹 리플레이 연결·재생 검증.
- OJN Hard/OJM 키음 뱅크도 웹에서 5 KOOL, MISS 0으로 완주.
- 정지·재개, 포커스 이탈 정지, 결과 화면, 새로고침 뒤 기록 유지 확인.
- Auto/리플레이 중 일반 건반 입력을 무시하는 정책과 완주 후 브라우저 콜백 종료도 확인.
- 웹 플레이어 버퍼를 20ms에서 100ms로 수정한 뒤, 8초 BGM이 게임 시각 8.0117초에 종료됨을 실제 브라우저 기록으로 확인. 수정 전에는 버퍼 부족으로 약 17초에 걸쳐 소비되는 사례가 있었다.
- HTTP 곡/에셋 경로, 잘못된 기록, 허용되지 않은 경로의 거부를 테스트.
- in-app 브라우저의 다운로드 완료 이벤트는 자동 검증 도구에서 받지 못했다. JSON 보기와 파일 가져오기는 확인했다.

WebAssembly 빌드·iframe 사용의 기준은 [Ebitengine 공식 안내](https://ebitengine.org/en/documents/webassembly.html),
컴파일러/실행 스크립트 버전 일치는 [Go 안내](https://go.dev/wiki/WebAssembly)를 참고했다.
