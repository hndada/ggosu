# 방 채팅

멀티 방의 오른쪽에서 접고 펼치는 채팅 패널이다. 방 메시지는 경기 상태와 별도로 유지한다.
서버는 `chat {text}`를 같은 방에 전달하고, 입장할 때 최근 12건을 `chat_history`로 보낸다.
방에는 최대 100건을 메모리에 보관하며 서버 재시작/방 삭제 후에는 남지 않는다.
전송자 ID·닉네임·시각·순번은 서버가 지정한다. 다른 방으로 메시지를 보내거나 이름을 바꿔서 보낼 수 없다.

## 웹

멀티 서버 `http://127.0.0.1:8090/`에서 접속하고 방에 들어간 뒤 오른쪽 `채팅`을 누른다.

- 대기실에서는 기본으로 펼친다. 새 메시지가 패널을 펼치거나 입력 포커스를 가져가지는 않는다.
- 펼치면 오른쪽에 겹쳐 표시한다. 본문 위치/폭은 바뀌지 않는다.
- 기본 폭은 360px이며 왼쪽 경계 드래그 또는 경계에 포커스 후 ←/→로 280~480px 사이를 조절한다. 좁은 창에서는 창 폭 안으로 제한한다.
- 접고 펼쳐도 대화·초안·스크롤을 유지한다. 경기 상태 변경도 이를 초기화하지 않는다.
- 지난 대화를 읽는 중에는 새 메시지가 와도 스크롤을 강제로 내리지 않는다. `최신으로`로 이동할 수 있다.
- Enter 전송, Shift+Enter 줄바꿈. IME 조합 중 Enter는 전송하지 않는다. 입력창은 내용에 맞춰 높이가 늘어나며 전송 버튼과 300자 제한을 표시한다.
- 전송 성공 ack를 받은 뒤에만 전송한 초안을 지운다. 그 사이 새로 작성한 내용은 지우지 않는다.
- 메시지는 HTML이 아닌 텍스트로 표시한다. 알림음은 기본으로 끈다.

컴포넌트는 `scenes/lobby/chat.js`, 배치는 `scenes/lobby/chat.css`, 색은 기존 `theme.css`의 변수만 사용한다.
동일 방의 대기실/진행/완료 상태에서 같은 컴포넌트를 유지한다.
곡 선택창에서는 채팅을 펼칠 때 오른쪽에 패널 폭과 간격을 확보한다. 곡 정보는 왼쪽, 채보 목록은 중앙, 채팅은 오른쪽에 나란히 표시하며 채팅을 접으면 목록이 빈 공간을 다시 사용한다.

## 채팅 · 알림 설정

환경 설정의 **채팅 · 알림** 탭 또는 채팅창 상단 **설정**에서 변경한다.
데스크톱은 실행 파일 옆 `data/settings.json`의 `chat`에 저장하며 네이티브 플레이 중에도 반영한다.
브라우저는 해당 사이트의 로컬 저장소에 저장한다. 도시 위치·친구 상태·관전자·게임 초대 옵션은 이 기능에 포함하지 않는다.

| 옵션 | 기본값 | 동작 |
|---|---|---|
| 채팅 ticker | 끔 | 접힌 채팅창의 최신 메시지를 5초 동안 표시 |
| 플레이 중 채팅 자동 숨김 | 켬 | 경기 시작 때 접기, F8로 직접 다시 열기 가능 |
| 내 이름이 언급되면 팝업 표시 | 켬 | 닉네임/`@닉네임` 언급 팝업, `mint`는 `chocomint`와 구분 |
| 새 채팅 메시지 팝업 표시 | 켬 | 이름 언급 이외 메시지의 팝업을 별도로 제어 |
| 내 이름이 언급되면 알림음 재생 | 끔 | 마스터·효과음 볼륨을 적용한 짧은 알림음 |
| 플레이 중 팝업 즉시 표시 | 끔 | 끄면 팝업과 언급 알림음을 경기 종료 뒤 한 번 처리 |

자신이 보낸 메시지·입장 이력·이미 최신 위치에서 읽고 있는 메시지에는 알림을 띄우지 않는다.
채팅을 열어 최신 대화를 읽으면 모아 둔 알림도 지운다. 팝업/ticker는 입력 포커스를 이동시키지 않는다.
메뉴와 네이티브 게임이 같은 메시지를 받아도 즉시 알림음은 게임에서만 재생하고, 미룬 알림은 메뉴로 돌아올 때 처리한다.

## 네이티브

`cmd/game`의 멀티 연결에 같은 방 채팅을 연결했다. F8 또는 오른쪽 Chat/Close 버튼으로 접고 펼친다. 솔로 플레이에는 채팅 버튼이 없다.
패널은 HUD 위에 겹쳐 표시하며, 1~18키 노트 필드 바깥으로 폭을 제한한다. 필드 위치·크기는 변하지 않는다.
입력창을 클릭하면 입력 모드가 된다. Enter 전송, 입력 중 Esc는 먼저 패널을 닫고 게임 제어 키로 전달하지 않는다. 입력 중이 아니면 Esc는 일반 플레이에서 정지·재개, 멀티에서는 퇴장으로 동작한다.
방에 연결하지 않은 솔로 플레이·리플레이에는 채팅창을 표시하지 않는다.
텍스트 입력 동안 플레이 키/설정 단축키를 분리한다. 경기는 계속 진행되므로 입력 중 노트를 놓칠 수 있다.
한글 조합은 Ebitengine 2.10의 `exp/textinput.Composer`로 처리한다. 물리 IME의 직접 조작 검증은 하지 않았다.
휠로 이전 메시지를 읽을 수 있고, 새 메시지가 와도 읽던 메시지 기준점을 유지한다.
검증 캡처용 `-chat-open` 옵션은 처음부터 패널을 펼친다.

## 제한과 검증

### 디버그 대화 발생기

멀티 서버 실행 후 `go run ./cmd/poc/chat`을 실행하면 **DEBUG 채팅** 방에서 가상 참가자 3명이
2초마다 대화한다. 이 방에 들어가 채팅을 확인한다. 사람이 만든 방의 플레이 중 채팅은
`go run ./cmd/poc/chat -room 실제방ID`로 확인한다. Ctrl+C로 발생기를 종료하면 봇들은 퇴장한다.
한글·영문·이모지·긴 문장·여러 줄·300자 메시지를 실제 채팅 경로로 전송하며 알림 소리는 없다.
속도·참가자·유한 실행 옵션과 확인할 동작은 [발생기 안내](../../cmd/poc/chat/README.md)에 있다.

### 전송 제한

메시지는 1~300자이며 줄바꿈 외 제어 문자는 거부한다. 같은 연결은 5초에 5건까지 보낼 수 있다.
채팅 오류는 네이티브 게임을 종료하지 않고 패널에 표시한다. 입력과 네트워크 쓰기는 별도로 처리한다.

- 방 간 격리·전송자 정보·경기 중/포기 후 전송·reset 후 이력·글자/빈 메시지/과다 전송 검사 통과.
- 접힘·초안·읽지 않은 개수·이전 메시지 기준점 유지 검사 통과.
- 1~18키 필드를 덮거나 재배치하지 않는 geometry 검사 통과.
- 실제 브라우저 두 클라이언트의 한글 송수신·입장 이력·초안 복원·미확인 개수 확인.
- 브라우저의 본문 위치/폭이 접힘·펼침 전후 동일했고, 지난 메시지를 읽던 scrollTop이 수신 전후 0으로 유지됨.
- 실제 네이티브 Auto 게임에서 웹에서 보낸 한글 메시지를 오른쪽 패널에 표시한 PNG를 확인.
- 전체 Go 테스트·vet·WASM 빌드와 frontend 스타일 검사 통과. 물리 키 입력/IME 후보창 조작은 미검증.

검증 파일: `artifacts/16-chat/chat-native.png`, `artifacts/16-chat/chat-panel.jpg`.
