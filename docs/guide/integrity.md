# 설정과 기록의 검증 및 복구

설정의 허용 범위 안에서 파일을 수정하는 것은 정상 변경이다. 잘못된 데이터는 감지하되,
손상이나 이전 버전의 데이터만으로 부정행위를 단정하지 않는다.

## 설정

설정을 정상 저장할 때 `settings.json.bak`에 검증된 같은 설정을 보관한다. 읽을 때 JSON 형식,
알 수 없는 필드, 설정 범위 및 관계를 검사한다. 손상된 기본 파일은 `settings.json.invalid-*`로
보존하고 유효한 백업을 복구한다. 백업도 사용할 수 없으면 기본값을 복구한다. 누락된 기본 파일도
유효한 백업이 있으면 복원한다. 권한·파일 I/O 오류는 자동 초기화하지 않고 반환한다.
백업은 로컬 복구용이며 변조 방지를 보증하는 서명은 아니다.

데스크톱은 복구 알림을 표시하고 네이티브 단독 실행은 표준 오류에 알린다.
브라우저 화면 설정도 별도 백업과 원본 보존 후 복구한다. 저장소 접근이 차단되면 원본을 삭제하지 않는다.
이미 시작한 플레이의 판정 조건은 파일 수정으로 다시 적용하지 않는다.

## 저장 결과

현재 규칙의 기록은 원본 채보 해시를 확인하고, 리플레이 오프셋·Mods를 적용해 입력을
공유 Go 판정 코드로 다시 처리한다. 점수·정확도·판정 수·콤보·평균 오차와 메타데이터가
다르면 계산값으로 복구하고 기존 파일은 `기록.json.invalid-*`로 보존한다.
채보와 입력을 확인할 수 있다면 점수 단독 변경과 수식에 맞춘 점수/판정 수 동시 변경 모두 복구할 수 있다.

JSON이 손상되거나 복구할 수 없는 기록은 별도로 격리하고 다른 기록은 계속 표시한다.
원본 채보가 없거나 변경되어 이전 해시를 찾을 수 없으면 기록을 보존하고 검증 불가로 표시하며,
최고 점수·달성 표시·PP·최고 기록 비교에서 제외한다. 이전 점수 규칙(version 1)은 원래 수치로 표시하며
현재 점수 규칙으로 자동 이관하지 않는다. `verification`은 저장된 문자열을 신뢰하지 않고 읽을 때 다시 결정한다.

브라우저의 기록 목록·결과 수신·가져오기·리플레이 선택도 `/api/validate`에서 서버의 채보로 계산한다.
수정 전 localStorage 문자열은 `ggosu:quarantine:*`에 보존한다. 네트워크·서버 오류는 격리 이유로 사용하지 않는다.

## 신뢰 범위

재계산은 입력 기록과 결과가 일치하는지 확인한다. 클라이언트가 채보·입력·실행 파일까지 통제하면
로컬 검사 자체를 우회할 수 있다. 플레이 모드·날짜·초기 배속 같은 클라이언트 메타데이터의 진위도
리플레이만으로 증명할 수 없다. 서버 기준 채보를 사용하는 멀티플레이 종료 검증은
[멀티플레이](multiplayer.md#종료-결과-검증)를 참고한다. 공식 랭킹이나 계정 인증은 별도 구현 대상이다.

## 검증

무음 채보로 손상된 설정의 백업/기본값 복원, 원본 바이트 보존, 정상적인 직접 변경,
점수 단독·동시 변경, 오프셋·Mirror·Random, hold·roll·mine·lift·fake,
프레임 간격별 MISS 점수, 부분 종료, 기록 격리, 채보 없는 기록 제외를 검사한다.
WebSocket 테스트는 변조한 종료 보고의 거부·이전 상태 유지·정상 결과 확인·다음 경기 초기화와
16KiB보다 큰 리플레이 전송을 검사한다.
