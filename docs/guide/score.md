# 110만점 점수 규칙

[hndada/gosu의 piano Scorer](https://github.com/hndada/gosu/blob/ec20db35ccf58f8d558304e4c69bf60ec89b9005/game/piano/scorer.go)와
[판정 가중치](https://github.com/hndada/gosu/blob/ec20db35ccf58f8d558304e4c69bf60ec89b9005/game/piano/mods.go)를 참고했다.
확인한 `level` 커밋은 `ec20db35ccf58f8d558304e4c69bf60ec89b9005`다.
기존 판정 시간창·노트 동작·입력 시각을 유지하고 점수 계산을 바꿨다.
판정 이름은 **KOOL·COOL·GOOD·MISS**다. 종전 `Perfect`·`Great` 필드는 읽을 때 `Kool`·`Cool`로 대응시키며 새 기록은 새 이름으로 저장한다.
명칭 변경은 버전 2의 점수 계산·정확도·최고 기록 비교 조건을 바꾸지 않는다.

## 계산

`N`은 채보 전체의 판정 개수다. Tap·Lift·Mine은 1개, hold·roll은 시작·끝 각각 1개이며 Fake는 제외한다.
플레이 도중에도 이 전체 개수로 나눠 점수를 누적한다.

```text
판정마다 얻는 점수 = (1,000,000 / N) × 판정 가중치
                  × (0.7 × Flow / 50 + 0.3 × Precision / 20 + 0.1 × KOOL 보너스)
```

Flow는 50, Precision은 20으로 시작한다. 판정에 따라 먼저 요소를 갱신한 뒤 해당 판정 점수를 더한다.

| 판정 | 가중치 | Flow | Precision | KOOL 보너스 |
|---|---:|---|---|---:|
| KOOL | 1 | 1 회복, 최대 50 | 1 회복, 최대 20 | 1 |
| COOL | 1 | 1 회복, 최대 50 | 1 회복, 최대 20 | 0 |
| GOOD | 0.5 | 1 회복, 최대 50 | 0으로 초기화 | 0 |
| MISS | 0 | 0으로 초기화 | 0으로 초기화 | 0 |

따라서 전부 KOOL이면 정확히 **1,100,000점**, 전부 COOL이면 **1,000,000점**,
전부 GOOD이면 **350,000점**, 전부 MISS면 **0점**이다.
MISS 이후에는 회복 과정에서도 점수가 줄며 회복한 요소가 이전에 잃은 점수를 돌려주지는 않는다.
판정 순서도 점수에 영향을 준다. 동일한 KOOL·COOL·GOOD·MISS 개수여도 순서가 다르면 점수가 다를 수 있다.

Accuracy는 점수/110만이 아니라 처리한 판정의 가중치 평균이다.
`(KOOL + COOL + GOOD × 0.5) / 처리한 판정 수`로 표시하므로 모두 COOL이어도 100%다.
Flow·Precision의 회복과 KOOL 보너스는 Accuracy 비율에 포함하지 않는다.

## 정수 누적

gosu의 부동소수점 누적과 시작 보정값 대신 정확한 정수 단위를 사용한다.
KOOL은 `28×Flow + 30×Precision + 200`, COOL은 `28×Flow + 30×Precision`, GOOD은 `14×Flow`를 누적한다.
표시 점수는 `누적 단위 × 500 / N`의 정수 몫이다. 판정마다 표시 점수를 반올림해 더하지 않는다.
이 방식으로 3·7·14·9999개 등 단위 점수가 나누어떨어지지 않는 채보에서도 만점이 정확하다.

## 기록·리플레이

새 결과 파일의 버전은 2다. 전체 판정 수·누적 단위·현재 회복 요소도 저장하여 점수 일관성을 검사한다.
기존 버전 1 파일은 원래 점수·정확도로 읽고 기록 목록에 **이전 점수 규칙**으로 표시한다.
기존 파일을 덮어쓰거나 판정 개수만으로 새 점수로 환산하지 않는다. 판정 순서 정보가 점수에 필요하기 때문이다.

최고 기록과 변화량은 버전 2끼리만 비교하며 일반 1배속 완주·같은 실제 배치 조건을 유지한다.
이전 기록의 리플레이는 그대로 재생할 수 있고 결과는 현재 110만점 규칙으로 다시 계산해 새 파일에 저장한다.
채보 해시, 판정 규칙 ID `ggosu-keys-v1`, 입력 시간축 `game-1x`는 유지한다.
판정 시간창을 바꾸지 않았으므로 입력 리플레이 규칙 ID와 결과 파일 버전을 따로 관리한다.

## MISS 점수 테스트

MISS는 해당 판정에서 점수를 더하지 않고 Flow·Precision·현재 콤보를 0으로 초기화한다.
이미 얻은 점수·누적 단위·최대 콤보는 유지한다. 이후 판정의 점수 회복이 느려지는 방식이다.

100개 Tap에서 하나만 입력하지 않고 나머지를 정확히 입력한 테스트 결과:

| MISS 위치 | 최종 점수 | 정확도 | 최대 콤보 |
|---|---:|---:|---:|
| 1번째 | 889,000 | 99% | 99 |
| 50번째 | 889,000 | 99% | 50 |
| 76번째 | 934,500 | 99% | 75 |
| 100번째 | 1,089,000 | 99% | 99 |

모든 경우 99 KOOL·1 MISS다. 1·17·250·5000 ms의 Update 간격에서 점수·판정 순서·콤보가 일치했다.
같은 판정 개수라도 MISS 위치에 따라 이후 회복 구간이 달라 점수가 다르다.

1000개 판정 기준의 회복 예시: KOOL 1,100점 → MISS 1,100점 → KOOL 1,229점 → COOL 1,287점 → GOOD 1,308점.
MISS 직후 추가 점수는 KOOL 129점, 그 다음 COOL 58점, GOOD 21점이다.
연속 MISS도 이미 얻은 점수에 변화를 주지 않으며 다음 GOOD은 Flow 1로 7점부터 회복한다.

LN 시작을 입력하지 않거나 KOOL/COOL/GOOD 범위 밖인 ±110 ms에서 눌러 MISS가 되면 시작·끝 모두 MISS다.
시작이 MISS인데 끝에서 KOOL을 받던 버그를 수정하고, hold·roll 모두 유지·반복 입력으로 되살아나지 않음을 검사했다.
hold 1개와 Tap 1개(총 3판정)에서 시작 MISS는 1 KOOL·2 MISS·43,000점,
정확한 시작 후 조기 해제 MISS는 2 KOOL·1 MISS·409,666점이다.

```powershell
go test ./internal/piano -run 'Test(MissScoreTrace|SingleMissPositionAndFrameCadence|HoldMissScore|MissedLongHeadCannotRecoverAtTail)$' -v -count=1
```

## 검증

Go 테스트로 채보 길이별 정확한 만점, COOL/GOOD/MISS 점수, 판정 순서에 따른 차이,
MISS 이후 Flow 50개·Precision 20개 회복, 부분 진행 점수, LN 끝·Fake의 분모 처리,
기존 기록 읽기·파일 보존·새 점수 리플레이를 검사한다.
JS 테스트는 이전 점수 규칙의 최고 기록 비교 제외와 점수·정확도 변화량을 검사한다.

실제 Wails Random·1.5배속 Auto와 웹 Mirror·2배속 Auto에서 모두 14 KOOL·1,100,000점을 확인했다.
Wails 기록 목록은 이전 규칙의 14,000점을 그대로 표시했고, 해당 Mirror 리플레이를 재생한 새 결과는
14 KOOL·1,100,000점이었다. 새 파일의 버전 2, 전체 판정 수 14, 누적 단위 30,800,
Flow 50·Precision 20·`game-1x`도 확인했다.
Go 테스트·정적 검사·JS 테스트·Wails 및 WASM 빌드가 통과했다.
판정 이름 변경 후에도 실제 Wails Auto 완주에서 KOOL 14·COOL/GOOD/MISS 0·1,100,000점을 확인했다.
Perfect/Great로 저장된 기존 기록 11개도 정상 로딩했고, 새 결과 JSON은 Kool/Cool 필드를 사용한다.
